# Batch Spec: EV-3a-03

## 目的

修 C5-EV-3a-03 单条（observe/metrics.rs:86-98，high performance）：
每个 Active ChangeRecord 都 `applied.iter().find(...)` → O(changes × applied)。
循环前建一次 `HashMap<&str, &AppliedRecord>`（key=mem_key）→ O(changes + applied)。

## 人类可读摘要

- family: performance-complexity（嵌套扫描 → 哈希索引）
- 覆盖 findings: 1
- 预估 diff: 1 file / +30/-3 lines（A 类，budget +40/-10）
- OCR 计划: r1, timeout 1800s, 期望 comments ≤ 3

## 核实的编译层事实（spec 前已核）

1. 行为保持关键点：`iter().find` 返回**首个**匹配；`HashMap::insert` 覆盖=
   保留**末个**。必须用 `entry(k).or_insert(v)` 保首个匹配语义，否则
   applied.jsonl 存在重复 mem_key 时结果漂移。
2. 纯函数 compute，无签名变更，调用点不受影响。
3. 既有测试 10 个 / 14 asserts（mod tests，:133-353）。
4. 同文件 :60/:66/:68/:86 的 medium/low（窗口边界 / max(1.0) 吞输入 /
   时间口径不一致 / 未来日期静默跳过）属其它簇，本批不动。

## 修法

- compute 内循环前建 `applied_by_key: HashMap<&str, &AppliedRecord>`
  （`entry().or_insert()` 保首匹配）；循环内改 `applied_by_key.get(...)`。
- 新增测试 1 个：applied 中重复 mem_key（首条 5 天前 / 次条 20 天前）→
  存活期取首条（锁死首匹配语义回归）。

## 红线

- 零语义变化（重复 mem_key 首匹配已锁测试）
- 不动同文件其它 findings（:60/:66/:68/:86 归其它簇）

## spec 起草后自查三条

1. `expected_files` = 1：src-tauri/src/evolution/observe/metrics.rs。
   纯函数内部重排，无 ripple。
2. budget = **A 类**：索引构建 +6、循环改写 -3/+2、测试 +22：
   估 +30/-3，预留 → **max +40/-10**。
3. finding 单条 fix 字段已写明无 ripple。
