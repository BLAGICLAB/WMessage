# Batch Spec: WA-01

## 目的

修 WidgetApp 域「输入/反序列化校验缺」簇：anchorFromRect 返回类型与 Anchor 接口结构性不一致（调用方易错接线）+ loadAnchor JSON.parse 零校验（坏 localStorage 值当合法 Anchor 直传下游）。

## 人类可读摘要

- family: input-validation
- 覆盖 findings: 2（全实修）
- 预估 diff: 3 files（2 改 + 1 新测试）/ +80/-25 lines
- OCR 计划: r1, timeout 1800s, 期望 comments ≤ 3（src/ 在 OCR 范围内）

## 两条 finding 原文核实

**① storage.ts:113（high，真）**：`anchorFromRect` 声明返回 `{ anchor: {x,y}; edge: Edge }`，与导出的扁平 `Anchor { x, y, edge }` 结构性不同——`anchor` 包装名与 `Anchor` 类型名冲突，调用方把返回值赋给 Anchor 变量或写 `result.anchor.x`/`result.x` 都会静默错接线。
**修法（finding 自荐方案 a）**：返回扁平 `Anchor` 直接。ripple 两个 call site（均已读原文确认）：
- `WidgetApp.tsx:285`（settle）：`const { anchor, edge: e2 } = anchorFromRect(...)` → `const na = anchorFromRect(...)`，后续 `{ ...anchor, edge: e2 }` × 2 → 直接用 `na`（`na.edge` 已是 e2）
- `WidgetApp.tsx:325`（collapse）：同上，`anchor.x/anchor.y` → `na.x/na.y`

**② storage.ts:79（high，真）**：`loadAnchor` 把 `JSON.parse(raw)` 盲 cast 成 `Anchor`——损坏/手改的 localStorage 值（缺 x/y、非数值坐标、未知 edge 如 "bottom"）会被当合法 Anchor 返回，下游解构即炸。loadSize 至少有数值范围校验，loadAnchor 应对齐做形状校验。
**修法**：形状校验——object 非 null + `x/y` 为 finite number + `edge` 在 `["right","left","top","float"]` allow-list，任一不过返回 null（与 loadSize 同策略：不清除坏值、不落盘）。Edge 数组常量提到模块级 `EDGES` 供校验复用。
