## 4. 批循环 SOP（每批固定流程）

1. **选簇**：从 triage §2（或用户拍板的 B 类项）选 ≤10 findings / ≤+500−300 行 / 单 family。
2. **spec**：写 `docs/batches/<批名>.spec.md`，模板照抄最近一份（`docs/batches/FE-08b.spec.md` 最简、`FE-07.spec.md` 最全）。必须含：目的/摘要/逐条处置（原文已核）/测试/红线/**自查三条**（expected_files 全路径、budget 两类、fix 字段 ripple）/自主执行规则/Stop 条件/机器可读 JSON/提交信息骨架/验证命令。→ docs commit（消息 `docs(batch): <批名> spec — …`）。
3. **改码** → `git add <精确文件列表>`（**不要 `git add -A`**，会把 untracked 旧 spec 卷进来）。
4. **gate**：`BATCH_SPEC=docs/batches/<批名>.spec.md python3 scripts/batch-verify.py docs/batches/<批名>.spec.md`，全 PASS 且 `commit_allowed: True` 才继续。
5. **三层**：`cargo fmt --check` + `cargo check`（src-tauri/ 内）、`npx --no-install tsc --noEmit -p tsconfig.json`、`bash scripts/test-all.sh`（~25s，全绿才继续）。
6. **OCR**：`mkdir -p ~/.openclaw/cache/<批名> && ocr review --format json --audience agent --exclude 'scripts/**' > ~/.openclaw/cache/<批名>/ocr-r1.raw.json 2>&1`（~1–5min，后台跑 + WaitFor）。解析：先 `grep -v '^\[ocr\]' raw > clean.json`，读 `comments[]`（字段 severity/path/start_line/end_line/content）。**规则：0 high 直接继续；同根因 medium/low 逐条采纳或不采纳（须有论证）；high 采纳后必须跑 r2 验证 0 high；high 判 FP 必须 reviewer。**
7. **code commit**：`cat > /tmp/<批名>-msg.txt <<'EOF' … EOF` + `BATCH_SPEC=… git commit -F`。message 结构：family 一句 → 逐条 file:line→修复机制 → 行为变更标注 → OCR 各轮处置 → FP/reviewer → spec 校正次数 → `D2: files=N(+a/-b) asserts=x→y tests=…` → `BATCH_SPEC=…` 尾行。
8. **triage 收口**（docs commit）：§0 顶部插执行日志（anchor = 第一条 `^- \[2026-09-2[45] ` 行前插）、§2 行尾加「→ 已清/部分清（批名，commit，§0 时间）」、§4 插 OCR 核验记录 + 新 B 类登记（anchor = `**已 triage（脚本 DOMAINS 12 域，不含 frontend）**: 145 unique` 行前）。时间戳用 `date '+%Y-%m-%d %H:%M %Z'` 实测。收口脚本模式：Write /tmp/xxx.py + `python3 -c "exec(open('/tmp/xxx.py',encoding='utf-8').read())"`（见 §6 坑 1）。
9. **push**：`git push 2>&1 | tail -3; echo "push_exit=${PIPESTATUS[0]}"; git rev-parse origin/main HEAD`，**两值必须相等**。建议 run_in_background + WaitFor。

**budget 超了**：先压注释；压不动 → unstage src → spec 校正（机器可读 JSON + 正文自查两处同步）→ docs commit → 重新 stage → 重跑 gate。校正 ≥3 次触发 reviewer 抽查。

**OCR 出新 high**：同根因→采纳进批；非同根因→stop 条件，停报人。

## 6. 踩坑清单（全部真实踩过）

1. **python3 跑含中文的 .py 脚本报 `Non-UTF-8 SyntaxError`**（本机 python 3.9.6 玄学）：脚本 `compile()` 明明通过却执行失败。解法：`python3 -c "exec(open('/tmp/x.py',encoding='utf-8').read())"`。
2. **gate 的 `assertions_min` 对 vitest 测试文件填 0**（正则只认 Rust assert 宏）。
3. **push 禁管道 head**：`git push | head` 的 SIGPIPE 会杀 pre-push hook。用 `| tail -3` + `echo "push_exit=${PIPESTATUS[0]}"`。
4. **pre-commit 的 tsc/vitest 跑 worktree 整体**：docs commit 也会被 worktree 里的类型错误/坏测试卡住（FE-07 踩过：docs commit 因未提交的测试文件 unused var 失败）。提交前确认 `npx tsc --noEmit` 干净。
5. **testing-library waitFor/findBy 在 vitest fake timers 下不自前进**（只认 jest fake）→ `findBy*` 永久挂起至超时。解法：初始填充用真 timers + userEvent，`vi.useFakeTimers()` 后只用 `fireEvent` + `await act(async()=>{})` 刷微任务；记得 `finally { vi.useRealTimers() }`（否则泄漏毒化后续用例）。
6. **`git add` 用精确文件列表**；`git add -A`/`git add .` 会把 untracked 旧 spec 卷进 staged 导致 gate file_set FAIL。
7. **spec 里 children/预期与实测不符**：numstat 以 staged 实测为准，budget 不够就校正 spec（校正 ≥3 次触发 reviewer）。
8. **OCR 偶发**：单次 test-all 挂 → 先隔离跑该测试再全量复跑，双过判 flaky（样本登记 triage §4，现有 4 例：端口 4763×2 + BotDisabled×1 + task_chat_exec duplicate_trigger×1）。OCR 的 `file_read` 参数越界 failure 已重试机制兜底，status=complete 即有效。
9. **profile.ts 等 vi.mock**：`vi.hoisted` 包共享 mock；`../profile` 相对路径以被测文件位置为准。
10. **同 path 的 OCR finding 有 dup ×2 条目**（fullscan JSON），按 start_line 过滤时会拿到重复原文，去重后再处置。
11. **机器可读 JSON 是 gate 的唯一事实源**：改 budget/expected_files 必须「JSON + 正文自查」两处同步改，漏一处 gate 与文档打架。
12. **多后台任务并发**：test-all 与 OCR 串在一条后台命令里时若被中止，靠 exit code 区分；复杂串行拆开跑。
