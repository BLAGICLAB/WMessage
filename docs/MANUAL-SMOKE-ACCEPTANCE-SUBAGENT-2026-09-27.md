## 2. 派发主链路（spawn → 子卡 → 围观 → 汇总）⭐ 核心链路

- [ ] ⭐ **spawn 非阻塞 + 立即告知**：在挂件/主窗聊天区发送：
  > 这个任务请派发子 agent 处理：调研 Tauri 2 与 Electron 的优劣，写一份对比报告存到产物目录。完成前先告诉我你已派发。

  预期：**几秒内**先收到「已派发」类回复（不等子任务跑完）；随后模型可继续对话 `[来源: SUBA-2 spawn 工具 / 设计 §5 非阻塞]`
- [ ] ⭐ **子卡出现在看板**：切到主窗看板「进行中」列 → 出现新卡，标题以 **🧩 子任务：** 开头；点开卡片可见【验收标准】小字（spawn 里的 criteria）+ **⏱ 预算徽标**（默认 30轮·600s）`[来源: SUBA-1 子卡双写 / SUBA-3 前端投影]`
- [ ] ⭐ **子 agent 会话出现在会话列表**：聊天区会话列表多出一个 **🧩 子任务：…** 会话；点进去能看到流式输出/工具折叠行在动（围观）`[来源: SUBA-2 runner interactive 流式]`
- [ ] **子会话首条消息是任务包装**：子会话历史第一条 user 消息含「[子任务派发]」「acceptance_criteria」「预算:」「产物目录:」「完成后必须输出以下 JSON」五段 `[来源: SUBA-2 render_task_wrapper / 设计 §8.5]`
- [ ] **主会话收到完成提示**：子任务结束后，回到**派发它的那个主会话**，出现一条提示行：「🧩 子任务已完成：<摘要>」（失败/取消/预算耗尽对应文案不同）`[来源: SUBA-3 subagent-finished 事件]`
- [ ] ⭐ **主 agent 汇总**：在主会话发「子任务结果如何？」→ 主 agent 调 check_subagent 后汇报**结论/产物路径/未完成项**，而不是把原文倒出来 `[来源: SUBA-2 check 工具 / 设计 §8.1 只消费摘要]`
- [ ] **收尾结果上卡**：子卡展开 → 「🧩 收尾结果」折叠条（含状态/置信度），点开见摘要与产物路径列表 `[来源: SUBA-3 result 投影]`
- [ ] **产物绑定回卡**：子卡的绑定文件里出现子 agent 产物（AI_Gen_Files/subagents/<id>/ 下文件），文件存在可打开 `[来源: SUBA-2 finalize 产物 bind / 设计 §13]`

## 3. 并发与排队（per-session 2 / global 3）

- [ ] ⭐ **同会话并发上限 2 + 排队**：发送：

## 4. 取消与预算（失控防护）⭐

- [ ] ⭐ **子会话停止键 = 取消子任务**：围观一个正在跑的 🧩 会话 → 点输入框右侧红 ■ → 该子任务很快停止；子卡回到**待办列**（不再留在进行中）；卡片/审计状态为 cancelled `[来源: SUBA-3 停止键分流 cancel_subagent / SUBA-1 取消回退 doing→todo]`
- [ ] ⭐ **/stop 同效**：新派发一个长子任务 → 在其 🧩 会话输入 `/stop` → 同样取消生效 `[来源: SUBA-3 /stop 分流]`
- [ ] **主对话取消**：派发后立即在**主会话**发「取消刚才那个子任务」→ 主 agent 调 cancel_subagent → 已派发的被取消（已是终态则如实告知）`[来源: SUBA-2 cancel 工具]`
- [ ] ⭐ **预算触顶 → budget_exceeded + 部分产物保留**：发送：
  > 派发一个 research 子任务：调研「2026 年主流大模型列表」写一份尽量详尽的报告（写入产物 report.md），验收标准=报告至少 500 字；预算 maxTurns=2, maxToolCalls=3, maxWallSeconds=20。跑完告诉我它的状态。

  预期：状态为 **预算耗尽（budget_exceeded）**；审计里 error 为 `max_turns` 或 `max_wall_seconds`；已写出的产物文件仍绑定在子卡上（部分结果不丢弃）`[来源: SUBA-2/3 预算三顶 / 设计 §6]`
- [ ] **排队中取消**：上面 §3 的 4 连派发进行中，对**排队中**的子任务在主会话发「取消还没开始的那两个子任务」→ 排队项被取消、不占并发槽，剩余正常跑完 `[来源: SUBA-3 WaitingGuard RAII 取消安全]`

## 5. 安全边界（递归禁用 / 白名单 / 主状态只读）

- [ ] ⭐ **递归禁用（服务端）**：审计验证（单测已锁双保险，此处验运行时面）：
  ```bash
  grep -E 'subagent_whitelist_deny|子 agent 不得派发' $DATA/bot.log | tail -3
  ```
  在子 agent 会话正常运行期间不应出现「子 agent 调 spawn 成功」的任何痕迹；工具清单里子 agent 看不到 spawn/check/cancel（可在子会话里发「列出你当前可用的工具」对照：无任务卡写工具、无编排工具）`[来源: SUBA-2 递归双保险 / 设计 §5]`
- [ ] **主状态只读**：子任务跑完后看板其他任务卡**未被**子 agent 改动（子 agent 白名单无任务卡写工具；subtasks 由系统代勾——子卡自己的子任务若被勾选，属系统代勾，正常）`[来源: SUBA-2 白名单 / 设计 §10.5]`
- [ ] **SSRF 回归**（➖ 可选）：让子 agent 抓取 `http://127.0.0.1:1/` 或 `http://192.168.1.1/` → 被拒（仅公网）`[来源: SUBA-2 SSRF 补测 0.0.0.0/:: / 设计 §10.3]`

## 6. 审计串链（可按 subagent_id 全链回放）

- [ ] ⭐ **审计事件全链**：
  ```bash
  grep -E 'subagent_(spawned|progress|done|failed|cancelled|budget_exceeded)' $DATA/bot.log | tail -15
  ```
  预期：一次派发可看到 spawned →（若干 progress）→ done/failed/…，行内带 `id: sa_…`、`task:`、`profile:`、`trace:`，同一子任务 id 可从头串到尾 `[来源: SUBA-1/2/3 事件全链 / 设计 §13]`
