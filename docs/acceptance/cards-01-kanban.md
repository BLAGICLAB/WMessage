### ACC-K-01 · 任务页 = 单人周时间网格（三列看板已退役）

- **SPEC**：1-01
- **层级**：L1+L2（L1 自动化 + L2 实机）
- **历史卡**：M91、M92（`docs/realmachine-smoke-test-2026-10-25.md`）
- **前置**：应用已启动；任务页至少有一张未排期任务卡
- **步骤**：
  1. 点左导航「任务」，等周网格渲染完成，截全屏。
  2. 读列头（自左至右）与左侧时刻轴（自上而下）。
  3. 把右侧任务池里一张未排期的卡拖到周一 10:00 附近的格子松手。
  4. 排一张 120 分钟的卡在周一 17:00 起，看它在周二的落点。
  5. 横向拖动一张已排期卡，看网格里有没有「换列」的插入位。
- **判据**：
  1. 【可观测】列头自左至右是「周一 … 周日」共 7 列；左侧时刻轴自上而下是 08:00 → 18:00，最上格 08:00、最下格 18:00。
  2. 【可观测】页面上没有「待办 / 今日 / 完成」三列看板：既没有这三列的列头，也没有列与列之间的卡片分隔竖线。
  3. 【可观测】步骤 4 的卡结束时间溢出 18:00 后折到次日：周一列只画 17:00–18:00 一段，周二列从 08:00 起画另一段，两段是同一张卡（标题相同）。
  4. 【可观测】步骤 5 横向拖卡时网格不出现任何换列插入位，松手后卡片仍留在原列。
  5. 【可核对】`grep -n "列=周一..周日，行=8:00–18:00" src/components/TaskTimeline/WeekGrid.tsx` 命中渲染口径注释；`grep -n "列=周一..周日，行=8:00–18:00" src/components/TaskTimeline/WeekGrid.tsx` 同一行注释是唯一的泳道定义。
- **证据**：截图（任务页全景含列头与时刻轴 + 拖拽中态 + 跨日两段卡）
- **失败处置**：本卡无专属审计事件，改查源码分家——`grep -n "列=周一..周日" src/components/TaskTimeline/WeekGrid.tsx` 无命中 = 泳道口径已改（卡片过期）；命中但机器上仍是三列看板 = 应用侧回归，开缺陷单
- **缺口补验**：拖拽落点写 planStart/End、30 分钟吸附、底缘拉伸、18:00 折入次日渲染未验

### ACC-K-02 · 排期：拖拽写起止、30 分钟吸附、移动 / 拉伸 / 拖回池清除

- **SPEC**：1-02
- **层级**：L2 实机
- **历史卡**：M91（`docs/realmachine-smoke-test-2026-10-25.md`）
- **前置**：任务页已打开；右侧任务池里至少有 2 张未排期卡
- **步骤**：
  1. 把第一张未排期卡拖到周一 10:07 附近的格子松手，读块上的时间行。
  2. 把第二张未排期卡拖到周一 13:50 附近松手。
  3. 拖住第一张块的下边缘往下拉，读结束时间怎么变。
  4. 按住第一张块的上部，把它整体拖到周一 15:00 位置。
  5. 把第一张块拖回右侧任务池，在池上松手。
- **判据**：
  1. 【可观测】步骤 1 落点不是 10:07，而是最近的 30 分钟整点 10:00；块的时间行显示「1 小时」。
  2. 【可观测】步骤 2 落点是 13:30 或 14:00 这类 30 分钟整点，不是 13:50。
  3. 【可观测】步骤 3 拉伸时出现把手提示（提示文案「向下拉伸改时长」）；拉完后结束时间变晚、起始时间不变。
  4. 【可观测】步骤 4 移动后起止同时平移、时长不变。
  5. 【可观测】步骤 5 块从网格消失、卡片仍留在任务池里（标题不变）；拖动过程里池边提示文案在「拖到时间轴上排期」与「松手取消」之间切换。
  6. 【可核对】`sqlite3 "<data_dir>/wmessage.db" "select plan_start, plan_end from tasks where id='<卡 id>';"` 两值相差 60 分钟、起始分位是 00 或 30；步骤 5 之后两列都为空（拖回池是清空排期，不是留旧值）。
  7. 【可核对】`grep -n "SNAP_MIN = 30" src/components/TaskTimeline/week.ts` 与 `grep -n "DEFAULT_DURATION_MIN = 60" src/components/TaskTimeline/week.ts` 命中吸附与默认时长常量；`grep -n "clampWindowMin" -A 3 src/components/TaskTimeline/week.ts` 命中落点钳制区间 [480, 1050]（08:00–17:30）。
- **证据**：截图（拖拽中态含落点提示 + 拉伸中态 + 拖回池后的网格）+ sqlite 查询输出
- **失败处置**：本卡无专属审计事件，改查源码分家——`grep -n "SNAP_MIN" src/components/TaskTimeline/week.ts` 无命中 = 吸附规则已改（卡片过期）；常量在但机器上落点不吸附 = 应用侧回归，开缺陷单
- **缺口补验**：拖拽写计划起止、30 分钟吸附、块可移动与底缘拉伸、拖回池清除均未专卡

### ACC-K-03 · 任务编辑浮窗：双击开、240ms 滑入滑出、跨页原位换任务

- **SPEC**：1-03
- **层级**：L1+L2（L1 自动化 + L2 实机）
- **历史卡**：M55、M91（`docs/realmachine-smoke-test-2026-10-25.md`）
- **前置**：任务页已打开；网格与任务池里各有至少一张卡
- **步骤**：
  1. 在网格里双击一张计划块，全程录屏。
  2. 浮窗停稳后量浮窗左缘与导航栏右缘的间距、浮窗宽度与上下留白。
  3. 不关浮窗，直接双击网格里另一张块；再双击任务池里的一张卡。
  4. 按 Esc 关浮窗，录屏看退场过程。
  5. 单击一次计划块，看是否打开浮窗。
- **判据**：
  1. 【可观测】步骤 1 浮窗从导航栏右缘向左滑入后停在固定位置（录屏逐帧：从出现到静止 ≤300ms，不出现二次跳动或重播）。
  2. 【可观测】浮窗宽 300px、上下各留 3px；左缘在导航栏右缘右侧 4px 处。
  3. 【可观测】步骤 3 浮窗留在原位、只把内容换成另一张卡（标题与备注随之变化），没有滑入滑出动画重播。
  4. 【可观测】步骤 4 按 Esc 后浮窗向左滑出再消失（退场 280ms），不是瞬间消失。
  5. 【可观测】步骤 5 单击计划块不打开浮窗（位移不超过 4px 按点击处理）。
  6. 【可核对】`grep -n "SLIDE_MS = 240" src/components/TaskTimeline/TaskEditorOverlay.tsx` 命中滑入时长；`grep -n "EXIT_MS = SLIDE_MS + 40" src/components/TaskTimeline/TaskEditorOverlay.tsx` 命中退场 280ms；`grep -n "LEFT = NAV_W + NAV_GAP" src/components/TaskTimeline/TaskEditorOverlay.tsx` 命中——浮窗左缘由导航宽常量算出，没有写死像素。
- **证据**：截图（浮窗停稳态含间距标注 + 原位换卡前后两张）+ 录屏（滑入与滑出各一段）
- **失败处置**：本卡无专属审计事件，改查源码分家——`grep -n "SLIDE_MS" src/components/TaskTimeline/TaskEditorOverlay.tsx` 无命中 = 动画时长口径已改（卡片过期）；常量在但机器上不滑入 = 应用侧回归，开缺陷单
- **缺口补验**：双击开浮窗、240ms 滑入滑出、跨页原位换任务不重播动画未验

### ACC-K-04 · 浮窗关闭拨杆：保存关闭 / 不保存关闭两条分支

- **SPEC**：1-04
- **层级**：L1+L2（L1 自动化 + L2 实机）
- **历史卡**：—（无：全库无实机卡）
- **前置**：任务页已打开；应用刚启动（用于验证拨杆不持久化）
- **步骤**：
  1. 按 ⌘N 开新建浮窗，看关闭键左侧有没有拨杆、默认什么状态、关闭键文案。
  2. 把标题改成「新卡测试」，把拨杆关掉，点关闭键。
  3. 回任务池看有没有多出新卡；再看回收站。
  4. 双击网格里一张已有卡，改标题与备注，关掉拨杆，点「不保存关闭」；再双击那张卡看标题与备注。
  5. 再打开第三张卡，看拨杆是不是又回到「开」。
  6. 关掉拨杆后退出应用，重开应用再开浮窗，看拨杆状态。
- **判据**：
  1. 【可观测】拨杆默认「开」，关闭键文案是「保存关闭」；拨杆关后文案变「不保存关闭」。每次打开浮窗（含换卡）拨杆都回到「开」。
  2. 【可观测】步骤 2 新建卡被取消：任务池里没有多出「新卡测试」，回收站里也没有它，页面上不留「新任务」空卡。
  3. 【可核对】`sqlite3 "<data_dir>/wmessage.db" "select count(*) from tasks where deleted_at is not null;"` 在步骤 2 前后计数不变——取消新建不是软删。
  4. 【可观测】步骤 4 只有本次改动的标题与备注回到打开浮窗时的值，未改动的字段保持打开时的值（不是整卡回滚到某个历史版本）。
  5. 【可观测】步骤 6 重开后拨杆仍是「开」——拨杆不持久化。
  6. 【可核对】`grep -rn "saveOnClose" src/components/TaskTimeline/TaskDetailPanel.tsx src/App.tsx` 命中拨杆状态与其重置逻辑；`grep -rn "保存关闭\|不保存关闭" src/components/TaskTimeline/TaskDetailPanel.tsx` 命中两条关闭键文案；`grep -n "discardEditor" src/App.tsx` 命中新建卡的回滚删除路径。
- **证据**：截图（拨杆开 / 拨杆关两种状态 + 关闭键文案 + 新建取消后的任务池）
- **失败处置**：本卡无专属审计事件，改查源码分家——`grep -rn "saveOnClose" src/components/TaskTimeline/TaskDetailPanel.tsx src/App.tsx` 无命中 = 拨杆已退役（卡片过期）；命中但机器上拨杆缺失或新建卡残留 = 应用侧回归，开缺陷单
- **缺口补验**：10-21 新增，全库无实机卡；不保存关闭两条分支完全未验
