# 任务页改造方案：周时间泳道

状态：**待拍板**（见文末决策点）。拍板后按「分批提交」小步落地，本文档随实现同步修订。

## 1. 目标

取消主窗口任务页的「待办 / 今日 / 完成」三列排列，改为**单人周时间泳道**：

- 横轴 = 一天内的时刻（8:00–18:00），纵轴 = 周一到周日；
- 未完成任务以统一大小的标题色块收进右侧**任务池**（毛玻璃、悬浮在泳道层上、可右缘折叠）；
- 色块拖到泳道即排期：自动写入 `planStart` / `planEnd`（默认 60 分钟）；
- 计划块可跨越日分割线（时长溢出 18:00 折入次日渲染）；
- 新建任务入口在页面左上，点开后左侧滑出**任务卡详情**（毛玻璃，与任务池同设计），内含计划时间编辑。

## 2. 范围

改：主窗口 `board` 视图（`KanbanBoard` 三列 → `TaskTimelinePage`）、任务数据模型（新增两个可选字段）、设计 token（新增毛玻璃与计划块色板）。

不改：

- `column` 数据契约（todo/doing/done）。挂件、归档、回收站、图谱、统计、bot 全部照旧读 column；本改造只换 board 视图的呈现，「完成」走详情面板按钮（复用 `set_task_column` 既有语义：写 completedAt、清 botAssigned 等）。
- 挂件（WidgetApp 用自己的 SortableTaskCard，不经过 KanbanBoard）。
- bot 工具 schema（v1 不暴露计划字段，见决策点 7）。

- 任务池折叠后缩为右缘竖条把手（图标 + 未完成计数角标），点击展开。
- 新建任务按钮在页头左上（全局 ⌘N 行为不变：切到任务页 + 打开详情面板新建卡）。

## 4. 交互规格

### 4.1 泳道

- 列头：`8`–`18` 共 11 档刻度（10 个小时格），每格内按 30 分钟细分吸附线。
- 行头：`周一 10/6` 式两段标签，**周一为一周首日**；今天行日期与行头用 accent 强调。
- 周导航：`‹ ›` 翻周，`今天` 快捷回当前周；非当前周不画「现在时刻线」。
- 现在时刻线：当前周且时刻落在 8–18 内时，画 2px accent 横线（左端圆点）；每分钟不动（打开页面与拖拽结束时校准即可，不做秒级定时器）。
- 计划块：绝对定位于所在日行内，`left = (start−8:00)/10h`，`width = duration/10h`；圆角 8px，块内只显示标题单行截断（左右 8px 内边距）。
- **跨日折行渲染**：`planEnd` 越过 18:00 时，块拆为多段——当日贴右缘段（右角开口）+ 次日自 8:00 起段（左角开口），两段同色并在衔接缘画 `»` / `«` 续接标记；跨到下周的部分在翻周后可见，本周右下角画溢出指示。起于 8:00 前的既有数据（导入/编辑产生）在首行贴左缘截断 + `«` 指示。
- 点击块 = 选中（1px accent 边）并打开左侧详情面板。

### 4.2 任务池

- 列出**全部未完成**的本人的用户任务（`column != done`、未删除、未归档、`origin=user`、本人——与现有 visibleTasks 过滤同口径，仅去掉 done）。
- 块统一大小（高 32px、宽撑满池内宽）：左侧 3px 色条 + 标题单行截断。已排期的任务也在池中，右端加时间角标（`二 9:00`）。
- 排序：已排期按 planStart 升序在前，未排期按 updatedAt 降序在后。
- 拖拽方向是双向的：池 → 泳道写入计划；泳道 → 池清除计划（`planStart`/`planEnd` 置 null）。
- 折叠状态存 localStorage（键 `wm-task-pool-open`），挂件面板折叠先例同思路。

### 4.3 拖拽（一个 DndContext 覆盖三个来源）

| 手势 | 结果 |
|---|---|
| 池块 → 泳道某位置 | `planStart = snap30(落点日+时刻)`，`planEnd = planStart + 60min` |
| 泳道块拖动 | 保持时长，`planStart` 跟随落点（30 分钟吸附，可跨行穿日） |
| 泳道块右缘手柄横向拉伸 | `planEnd = snap30(指针时刻)`（可越过 18:00 折入次日；最短 30 分钟） |
| 泳道块 → 池 | 清除 `planStart` / `planEnd` |

- 落点解析用指针相对网格原点的偏移（dnd-kit `activatorEvent` + 网格 rect 反解），落出网格边界时钳制到最近合法格。
- 拖拽过程显示占位虚影（DragOverlay 渲染同款块 + 60% 透明度），落点格高亮。
- `planEnd > planStart` 恒成立（拖动/拉伸路径钳制），存前校验，非法不写。

### 4.4 任务卡详情面板（左）

- 打开时机：点泳道块 / 点池块 / 新建任务。关闭：X、Esc。
- 内容复用 `TaskCardContent` 的编辑字段（标题、备注、标签、文件、子任务、due），新增**计划时间**区块：
  - 开始：`datetime-local` 输入（`YYYY-MM-DDTHH:mm`，与 due 同格式）；
  - 时长：30 分钟步进器（`− 60min +`），快捷 30/60/90/120；
  - 「清除计划」按钮；planStart 与 planEnd 联动校验同 4.3。
- 底部操作：`标记完成`（set_task_column done）、`删除`。完成语义完全走既有服务端命令。
- 视觉与任务池同一毛玻璃面板规格（同圆角、同边线、同模糊），仅结构不同。

## 5. 设计语言

现有体系：亮度分档三层表面（`--bg → --surface → 悬浮`）、1px `--edge` 边线、`nm-card` / `nm-inset` 语义类、亮暗双主题。毛玻璃是本次唯一新增质感，也是整页的记忆点——其余一切保持安静。

### 5.1 新增 token（main.css）

```css
/* 亮 */
--glass-bg: rgba(255 255 255 / 0.62);
/* 暗 */
--glass-bg: rgba(22 25 33 / 0.58);

.glass {
  background: var(--glass-bg);
  backdrop-filter: blur(18px) saturate(1.4);
  border: 1px solid var(--edge);
}
@supports not (backdrop-filter: blur(1px)) {
  .glass { background: var(--surface); }  /* 退化不透明，保对比 */
}
```

阴影纪律：悬浮面板只给极轻一层（现体系靠亮度分档，不引入粗阴影）。

### 5.2 计划块色板

现有标签徽章无色彩体系（nm-inset 中性灰），色块色板为新增，低饱和、亮暗主题各调明度：

| token | 色相 | 亮主题底色（约） | 用途 |
|---|---|---|---|
| --plan-blue | 蓝 | `color-mix(色 14%, var(--surface))` | 首个标签哈希 → 6 色之一 |
| --plan-teal | 青 | 同上 | |
| --plan-green | 绿 | 同上 | |
| --plan-amber | 琥珀 | 同上 | |
| --plan-violet | 紫 | 同上 | |
| --plan-slate | 中性 | 同上 | 无标签缺省 |

规则：取任务首个标签做稳定哈希映射（同标签恒同色）；无标签 = slate。左条用纯色、块底用 14% 混色、文字 `--t1`。红/橙系错误语义色不入板。

### 5.3 网格与层阶

- 小时刻线：`--edge` 40% 透明；正午线稍强；日行分隔：`--edge` 实线；今天列底：accent 6% tint。
- 层阶（低→高）：泳道网格 → 现在时刻线 → 详情面板（文档流）→ 任务池悬浮层 → 拖拽 DragOverlay。
- 动效只响应动作：面板滑入 160ms ease-out、折叠 160ms、拖拽幽灵跟随指针；不做常驻动画；`prefers-reduced-motion` 全部退化为直切。

## 6. 数据模型与后端

### 6.1 字段

`Task` 新增两个可选字段（`src/types.ts` + `src-tauri/src/db/tasks.rs` 同步，serde camelCase）：

```ts
/** 计划开始 "YYYY-MM-DDTHH:mm"（与 due 同格式）；缺省 = 未排期 */
planStart?: string;
/** 计划结束，恒 > planStart；缺省 = 未排期 */
planEnd?: string;
```

### 6.2 Rust 侧改动（tasks.rs）

1. `Task` 结构体加 `plan_start: Option<String>` / `plan_end: Option<String>`（`#[serde(default)]`，老数据/老导入信封零改动兼容）。
2. 新列常量（沿 OWNER_/ACCEPTANCE_ 先例各自独立成组）：

   ```rust
   pub(crate) const PLAN_TASK_COLUMNS: [(&str, &str); 2] =
       [("plan_start", "TEXT"), ("plan_end", "TEXT")];
   ```

   注册进 open_db 幂等 ALTER 迁移；legacy 迁移测试 fixture 同步。
3. `task_patch` 白名单加 `planStart` / `planEnd`：字符串校验 `YYYY-MM-DDTHH:mm` 格式（同 due 的宽松校验路径），null = 清空落库，缺键 = 保留——语义与现有可选字段一致。
4. 导出/导入信封：serde 自动带出新字段，无需额外处理。

### 6.3 前端接线

- `updateTask`（task_patch 通道）原样携带新键；拖拽落点只发 `{planStart, planEnd}` 两键的最小 patch。
- RMW `expectedUpdatedAt` 防覆盖机制不变。

## 10. 待拍板决策点

1. **池的范围**：按你的原话列「未完成的全部任务」（已排期的带时间角标，双向拖拽不冲突）；备选是只列未排期任务。
2. **「跨天穿透日分割线」的落地语义**：本方案 = 时长溢出 18:00 自动折入次日 8:00 继续渲染（分段 + 续接标记）；如果你指的是「8–18 之外也可视」（如滚动扩展到 6–22），需要改列头方案。
3. **吸附粒度 30 分钟**（落点、拉伸同粒度；默认时长 60 分钟）。
4. **周一为一周首日**。
5. **「今日/doing」失去专属视觉**：doing 任务混在池与泳道里（数据契约不动）。
6. **色板新增**：6 色低饱和板按首个标签取色，无标签中性色——这是新的色彩体系，请确认。
7. **bot 工具 schema v1 不动**：create_task/edit_task 不暴露计划字段（人工排期先行）；后续若要让 bot 自己排期，再加字段 + 重生成 tools_baseline fixture。
