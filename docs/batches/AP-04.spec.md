## 核实的编译层事实（spec 前已核，非凭印象）

1. `Request::upgrade` 返回 `Box<dyn ReadWrite + Send>`（vendor request.rs:305-334）；
   `ReadWrite` trait = `Read + Write`（request.rs:503），**无超时方法、无 AsRawFd**
   → 应用层无法补写超时，必须走 vendor patch。
2. vendor patch 有既有治理流程：先例 `10acf42`（读超时 slowloris patch，
   connection.rs:28-32 + lib.rs:103/118-141 `HTTP_READ_TIMEOUT_MS`），
   `PATCHES.md` 登记 + `[wmessage patch]` 标记 + `scripts/ci-guard-tiny-http-vendor.sh`
   守卫。**vendor 改动非 architecture_blocker**。
3. socket option 作用于底层 socket 本身：accept 时 `set_write_timeout` 后，
   upgrade 拆出的 writer（同一 socket 的 clone 链）写路径同样受限——
   与既有读超时 patch 同机制（其注释明示「超时作用于同一 socket 的所有读」）。
4. 乱序投递根因属实：`broadcast`（api_server.rs:121-154）`next_id.fetch_add`
   在锁外、`try_send` 在 clients 锁内——并发广播 A(id5)/B(id6) 可 B 先入队，
   writer 端 `id <= last_sent` 去重静默丢迟到的 id5。同根连带：id 落盘
   （:126-129）也在锁外，并发可致先 6 后 5 落盘 → 重启 id 回退复用。
5. 锁序安全：全仓无嵌套持锁（sse.rs:130 单锁 clients；mod.rs:504 单锁 clients；
   replay 单锁 history；旧 broadcast 顺序锁不嵌套）→ 新嵌套 clients→history
   是唯一嵌套点，无死锁对。
6. id 单调性构造保证：`fetch_add(1, SeqCst)` 进程内严格递增；`persisted()`
   跨重启恢复（id_path atomic_write）；hub 换代 = writer 全停（api_stop）。
7. 写超时行为级测试需填满 kernel send buffer（平台相关、MB 级写入、flaky），
   **不加行为测试**——对照读超时 patch 的测试只有 accept 级 slowloris 回归
   （api_server.rs:333，本批不动它，须保持绿）。改宣：broadcast 有序性新增
   并发回归测试（确定性，非 timing 依赖）。

## 修法（逐条）

### finding 1：sse.rs:196（high，writer 写无超时 → stop 无法停写死的 writer，线程真泄漏）

- `vendor/tiny_http/src/lib.rs`：新增 `pub static HTTP_WRITE_TIMEOUT_MS:
  AtomicU64 = AtomicU64::new(30_000)`（带 `[wmessage patch]` 标记 + 取舍注释：
  单次 write syscall 级；作用同一 socket 全部写，含普通响应与 SSE upgrade 流；
  卡死对端 30s 内写报错 → writer 退出可 join）。**同时修订
  `HTTP_READ_TIMEOUT_MS` 注释尾弹「只影响读，不影响写：SSE 不受影响」——
  本批后该句过时**（读超时仍只管读；写侧由新 static 接管）。
- `vendor/tiny_http/src/connection.rs`：accept Tcp 分支既有
  `set_read_timeout` 旁加 `set_write_timeout`（同 `[wmessage patch]` 注释、
  同失败忽略策略）。Unix socket 分支不动（与读超时 patch 一致）。
- `vendor/tiny_http/PATCHES.md`：§2 头「共 2 处」→ 3 处；新增 §2.3
  登记写超时 patch（符号/行号范围/取舍）；§5 升级记录加行
  （2026-09-24 / 0.12.0 / AP-04 本 commit）。
- `sse.rs:162-165` 注释修订：原「ResponseBox 不提供 set_write_timeout，
  故通过 recv 端超时兜底」过时 → 改为「写超时由 vendor patch 在 accept 级
  设置（HTTP_WRITE_TIMEOUT_MS 30s，单次 write syscall 级），写死连接
  ≤30s 内报错退出」。

### finding 2：sse.rs:183（high，replay 去重契约未强制/未文档化，乱序投递静默丢事件）

- `api_server.rs:121-154` `broadcast` 单临界区化：clients 锁内依次
  fetch_add → id 落盘 → history push → try_send 推送（锁序 clients→history
  为全仓唯一嵌套点，已核无死锁对）。clients 锁 poison 由「静默跳过推送」
  改 C3-1 形态（eprintln `[mutex_poisoned]` + into_inner 恢复）。
  行为变更：① 每 client 队列事件序 = id 单调序（修复目标）；② id 落盘
  不再并发乱序；③ poison 从静默跳过变恢复+留痕。事件频率人级，
  锁内文件 I/O 可忽略。
- `sse.rs`：replay_max 快照（replay 结束时的 last_sent）+ live 分支丢弃臂
  加异常留痕——`id <= last_sent` 且 `id > replay_max` 时 eprintln
  `[sse] out-of-order live event dropped`（修复后正常路径永不触发，
  触即发 = broadcast 临界区被破坏的防御信号）；重放窗口内合法重复
  （id ≤ replay_max）不留痕（每次重连都有，留痕 = 噪音）。
- 契约文档化：sse.rs:179-182 去重注释扩写 + api_server.rs EventHub::broadcast
  注释声明「id 进程内严格单调（fetch_add 于 clients 锁内）、跨重启单调
  （persisted id_path）、hub 换代 writer 全停故无跨代复用」。
- 新增测试 `broadcast_concurrent_delivery_order_matches_id_order`
  （api_server.rs tests）：2 线程各广播 50 条，client 队列收集 100 条
  断言严格递增 + 计数 = 100 + last_id = 100。确定性，非 timing 依赖。
