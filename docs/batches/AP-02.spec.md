# AP-02 spec — C5-AP-02 token 写 symlink + 权限窗口（api_auth.rs:73，1 条）

## 目标 finding

**api_auth.rs:73**（high）：`write_token_file` 用 `truncate(true)` 打开——跟随 symlink；
`mode(0o600)` 只对新建 inode 生效；存量 0644 文件在 truncate→结尾 chmod 之间，
token（bearer 等价物）以旧权限落盘，同机其他用户可读。

## 修法（tmp + rename 原子写，一次杀两个缺口）

重写 `write_token_file` 为：

1. tmp 路径 = 同目录 `{file_name}.tmp`（复用 db::atomic_write 的命名约定）。
2. tmp 用 `OpenOptions write+create+truncate + mode(0o600)` 打开——新建即 0600，
   **无可读窗口**（atomic_write 的 `fs::write` 走 umask 0644 不满足 token 场景，故不直接复用）。
3. 写入失败 → best-effort 删 tmp → Err。
4. `std::fs::rename(tmp, path)`——rename 替换目录项本身，**不跟随 symlink**
   （目标位置是 symlink 时被整个替换，token 不会写进 symlink 指向的文件）。
5. rename 后对目标补 `tighten_token_permissions`（belt & suspenders；tmp 0600 已保证，
   防极端文件系统 rename 权限继承差异）。

行为变更：token 路径若是 symlink，旧行为=跟随写入目标文件，新行为=symlink 被替换为
普通文件（fail-closed 方向，正是 finding 建议）。token 轮换（覆盖写）不受影响。

不引 libc / 不加依赖；不用 `create_new`（会误杀正常覆盖写）。
