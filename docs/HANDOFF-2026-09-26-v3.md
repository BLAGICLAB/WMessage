## 6. 批循环 SOP（不变，照旧）

1. 选簇（≤10 findings / ≤+500−300 行 / 单 family）
2. spec：`docs/batches/<批名>.spec.md`，模板照 `docs/batches/P3-BUG-2.spec.md`（最新最简）；
   机器可读 JSON 是 gate 唯一事实源，改预算/文件清单必须 JSON+正文两处同步
3. 改码 → `git add <精确文件列表>`（**禁 -A**，untracked 会卷入）
4. `BATCH_SPEC=... python3 scripts/batch-verify.py ...` 全 PASS 且 commit_allowed:True
5. 三层：cargo fmt/check（src-tauri 内）+ `npx tsc --noEmit` + test-all 全绿
6. OCR r1（0 high 继续；high 采纳后 r2 验 0 high；证据落 ~/.openclaw/cache/<批名>/）
7. code commit：family 一句 + 逐条 file:line→机制 + 行为变更 + OCR 处置 + `D2: files=N(+a/-b)…` + `BATCH_SPEC=…` 尾行
8. triage 收口 docs commit → push（贴两值相等）
9. **红线：禁 --force/--force-with-lease；已 push 的 commit 禁 amend**（本会话教训：
   push 后 amend 会分叉，reset --hard 仅限当前批回滚，D2 偏差走 docs 勘误）

## 7. 踩坑清单（本会话新增 ★，其余见 AUTO-LOG/PHASE2-TRIAGE §5）

- ★ **cwd 漂移**：Bash 调用间 cwd 会停在上次 `cd` 的目录——所有 git/pytest 命令前
  `cd /Users/renshi/Projects/wmessage &&`（本会话踩 ≥5 次，含一次 docs commit 误入 src）。
- ★ **docs commit 前必须 `git restore --staged src-tauri src`**：只要有 src staged，
  pre-commit 就强制 BATCH_SPEC 并把 src 扫进 docs commit。
- ★ **echo/管道后的 `${PIPESTATUS[0]}` 必须紧贴**：`cmd | tail -2; echo exit=…` 拿到的是
  tail 的退出码——push 后验证两值相等才是硬标准。
- ★ **rustfmt 会重排多行闭包**：budget 按格式化后实测；±10 行级别的估差常态化，
  spec 校正 ×1~2 是正常（≥3 触发 reviewer 抽查）。
- ★ **OCR fullscan 的 medium/low 段 FP 率显著高**（security 25 中 3 FP）：medium/low 只当
  「线索池」，不当工单。
- ★ **amend 只限未 push**；已 push 的 commit 出错 → 后续 commit 勘误。
- ★ **OCR fullscan 输出里 `**` 是掩码/转义痕迹**：SIZE_KEY/STORAGE_KEY 这类「值是 ***」的
  finding 先 od -c 现读原文件再判——本会话两例全 FP。
