## 逐条处置（原文均已核 + 用户拍板 2026-09-26）

**实修 ① src-tauri/src/bot_py.rs:694/:705（NEW-1，测试代码）**：两处 silent into_inner 补 eprintln `[mutex_poisoned]`（同 NEW-2 机械形态）。

**实修 ② src-tauri/src/bot/config/audit.rs:19（NEW-3a）**：escape_for_log 只转义 `|`/`\n`/`\r`，缺 `\t`/`\0`/ESC 等控制字符与 U+2028/U+2029（与 api 域 sanitize_log_line 全集不一致）。
**修法**：`\n`/`\r` 保留短形式，其余 `char::is_control()` → escape_default 形式 + U+2028/U+2029 显式臂（照 sanitize_log_line 语义），`|`/`| ` 表格转义保留。新增单测锁全集。

**实修 ③ src-tauri/src/audit.rs + middleware.rs + api_server.rs + migration/run.rs + bot_scheduler.rs（NEW-4）**：panic payload 提取 2 处命名 fn（middleware/api_server，"non-string panic payload"）+ 3 处内联（run.rs "未知 panic" / bot_scheduler ×2 "非字符串 panic"）共 5 处重复。
**修法**：crate::audit 新增 `pub(crate) fn panic_message(payload: Box<dyn Any + Send>) -> String`（canonical 文案 "non-string panic payload"），middleware/api_server 删本地 fn 改调，run.rs/bot_scheduler 内联改调（文案随 canonical 统一——日志措辞变化，行为不变）。
**ripple**：run.rs/bot_scheduler 日志措辞 "未知 panic"/"非字符串 panic" → "non-string panic payload"（纯文案）。

**实修 ④ src-tauri/src/db/paths.rs:48（NEW-5）**：atomic_write rename 失败残留同级 .tmp（API-B 测试暴露）。
**修法**：rename 失败臂 best-effort `remove_file(&tmp)`（照 AP-02 write_token_file 先例）+ 单测（dst 为目录 → rename 失败 → tmp 不残留）。

**零代码 ⑤ NEW-3b**：audit_log rotate+append 撕裂——现读 stale：rotate 在锁外（注释钉死容错「最坏=当次不轮转，下次补上」）+ append 在 BOT_LOG_LOCK 内。登记 triage。
