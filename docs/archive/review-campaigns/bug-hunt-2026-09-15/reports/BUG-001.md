# BUG-001 — `MutexGuard` 跨 `.await`(async 测试中)

## 位置
- `tests/skill_e2e.rs:270` (static decl) + `:371, :470, :527, :621` (4 处 lock 调用)
- `tests/task_chat_exec.rs:27` (static decl) + `:95, :228, :276` (3 处 lock 调用)
- 共 2 文件 / 7 处 clippy `await_holding_lock` warning

## 严重度
**S2**(latent — 当前 tokio 单线程 runtime 不表现,但切 multi-thread / 增加并行测试时 flaky)

## 类别
并发 / lint — clippy `await_holding_lock`

## 复现步骤
```bash
cd src-tauri
cargo clippy --tests -- -W clippy::await_holding_lock 2>&1 | rg "is held across an await"
```
输出(修复前):
```
warning: this `MutexGuard` is held across an await point
  --> tests/skill_e2e.rs:371:9
  --> tests/skill_e2e.rs:470:9
  --> tests/skill_e2e.rs:527:9
  --> tests/skill_e2e.rs:621:9
  --> tests/task_chat_exec.rs:95:9
  --> tests/task_chat_exec.rs:228:9
  --> tests/task_chat_exec.rs:276:9
```

## 根因
`std::sync::Mutex` 的 `lock()` 返回同步 `MutexGuard`,在 `#[tokio::test] async fn` 内通过 `let _serial = ...lock().unwrap_or_else(...)` 持续持有到函数末尾。期间所有 `.await` 期间,guard 仍存活:
- 单线程 runtime 不表现(无 worker 可被抢占)
- multi-thread runtime 下,持锁 task 可被调度到另一 worker;若另一 task 同时尝试锁 → 持锁跨 await 增加死锁/惊群风险
- 若 task 被 `cancel` (drop 闭包未跑),guard 提前 drop,其他 waiter 可能惊群

## 修复方案
改用 `tokio::sync::Mutex`(async-aware),配 `LazyLock` 包装初始化(`tokio::sync::Mutex::new()` 不是 `const fn`,无法直接 `static X: Mutex<()> = Mutex::new(())`)。

```rust
// 修复前(std::sync::Mutex,锁跨 await)
static SKILL_SCHED_TEST_LOCK: Mutex<()> = Mutex::new(());
// ...
let _serial = SKILL_SCHED_TEST_LOCK
    .lock()
    .unwrap_or_else(|e| e.into_inner());

// 修复后(tokio::sync::Mutex,async-aware)
static SKILL_SCHED_TEST_LOCK: LazyLock<tokio::sync::Mutex<()>> =
    LazyLock::new(|| tokio::sync::Mutex::new(()));
// ...
let _serial = SKILL_SCHED_TEST_LOCK.lock().await;
```

## 风险
- **低**:`tokio::sync::Mutex` 与 `std::sync::Mutex` 的语义差异:tokio 版本不可 `try_lock()`,仅 `.lock().await`;本测试场景只调用 `.lock()`,无影响
- **低**:`LazyLock` 初始化 lazy-on-first-access;本测试 `_serial` 在测试体首行立即访问,等价于立即初始化,行为不变
- **无**:`tokio::sync::Mutex` 没有 poison 语义,所以 `.unwrap_or_else(|e| e.into_inner())` 链被消除是正确的(测试不再需要 poison 恢复)
