# Batch Spec: WA-03

## 目的

修 WidgetApp 域「dnd-kit 可达性/事件冲突」簇：SortableWorkspaceCard 键盘拖拽不可达（attributes 在 wrapper、手柄 span 无 tabIndex）+ SortableTaskCard 拖拽完成后 pointerup 衍生的 click 误触发选中切换。

## 人类可读摘要

- family: dnd-a11y-event
- 覆盖 findings: 2（全实修）
- 预估 diff: 3 files（2 改 + 1 新测试）/ +80/-8 lines
- OCR 计划: r1, timeout 1800s, 期望 comments ≤ 3

## 两条 finding 原文核实（两组件全文 + caller 已读）

**① SortableWorkspaceCard.tsx:23（high，真）**：`useSortable` 的 `attributes`（role="button" / tabIndex / aria-roledescription / aria-pressed）铺在 wrapper div 上，而 KeyboardSensor 激活用的 `listeners` 经 render prop 交给 caller 的 `<span {...listeners}>☰</span>`——span 无 tabIndex 不可聚焦，键盘用户永远到不了手柄；屏幕阅读器却把整张卡报成可排序按钮。
**修法**：render prop 改传**合并手柄 props**（`{ ...attributes, ...listeners }`），wrapper div 不再铺 attributes。caller（WidgetApp.tsx:746 `(listeners) => <span {...listeners}>`）**源码零改动**——spread 语义不变，只是对象里多了 attributes 键。类型：render prop 参数类型从 `DraggableSyntheticListeners | undefined` 放宽为 `(DraggableSyntheticListeners & DraggableAttributes) | undefined`（dnd-kit 导出的 attributes 类型）。

**② SortableTaskCard.tsx:55（high，真）**：拖拽结束后浏览器在同一元素上派发 click，wrapper 的 `onClick = selectMode ? onSelect` 无激活距离/拖拽守卫——selectMode 下完成一次排序会误切选中。
**修法**：`useDndMonitor` 挂 `onDragStart`/`onDragEnd`/`onDragCancel`——`active.id === task.id` 时置 `wasDraggingRef.current = true`，end/cancel 时 `setTimeout(0)` 复位（click 在 pointerup 后、timeout 前派发，时序上守卫有效）；onClick 包一层 `if (wasDraggingRef.current) return`。组件本就在 DndContext 内（useSortable 同要求），useDndMonitor 安全。

## 测试（新文件 src/components/WidgetApp/sortable-a11y.test.tsx）

vitest + jsdom + testing-library，组件包在 DndContext + SortableContext 内渲染：
- WorkspaceCard：手柄（render prop 收到的对象 spread 到 span）有 `tabindex=0` + `role="button"` + `aria-roledescription`；wrapper div **无** tabindex/role
- TaskCard：`vi.mock("../TaskCardContent")` 简化后，selectMode 下普通 click → onSelect 被调（回归：守卫不误伤正常点击）

（拖拽→click 的完整集成路径需真实 dnd 拖拽会话，jsdom 成本过高；守卫逻辑 = ref + 事件时序，单测覆盖正常点击回归 + WorkspaceCard a11y 属性，拖拽路径由 WidgetApp 既有测试兜底。）
