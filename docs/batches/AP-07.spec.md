# Batch Spec: AP-07

## 目的

修 C5-AP-07 单条（api.rs:101）：TaskStore sync trait 的 `block_on` 桥接依赖
「调用方在普通 std::thread」这一**未文档化、无运行时检查**的隐式约定——
按 finding 给的轻量选项落地：显式运行时检查 + 指向约定的 panic 消息 +
trait 契约文档化（不做 async trait 改造 = 签名 ripple 扩 scope）。

## 核实的编译层事实（spec 前已核）

1. TaskStore 两实现：MemStore（:54，纯 sync 无 block_on，不动）/
   TauriStore（:100，load/upsert 各一处 `tauri::async_runtime::block_on`）。
2. 调用方全在 tiny_http per-request std::thread（api_server worker），
   现状安全；风险是未来误从 runtime 线程调用 → panic/死锁且消息不指因。
3. tokio 是直接依赖（Cargo.toml:59，features `sync`/`time`），**无 `rt`**；
   `Handle::try_current()` 需 `rt` → 本批加 feature（非新依赖，lock 不变）。
   dev-dependencies 已有 macros/rt-multi-thread（#[tokio::test] 可用）。
4. 不用 catch_unwind 包 block_on：会误吞 db fn 自身 panic 并误标为约定违反
   （误报）；try_current 检查精确零误报。tauri 全局 runtime 为 multi-thread，
   runtime 线程上 block_on 必 panic（死锁形态不适用），检查 + 明确消息足够。
5. api.rs 无测试模块（0 assert）→ 新增 tests 模块 + 1 个 #[tokio::test]。

## 修法

- `src-tauri/Cargo.toml`：tokio features 加 `rt`。
- `src-tauri/src/api.rs`：
  - 新增 `assert_sync_bridge_caller()`（pub(crate) 不必，私有即可）：
    `Handle::try_current().is_ok()` → panic 消息点名约定（「TaskStore::load/
    upsert 是 sync 桥接，禁止在 tokio runtime 线程调用；调用方须在普通
    std::thread（tiny_http worker）」）。
  - TauriStore::load/upsert 的 block_on 前先调检查（替换 B3 旧注释为
    「约定已显式化并运行时强制」）。
  - TaskStore trait doc 补契约段：sync 方法经 block_on 桥接 async db fn，
    调用方必须在非 runtime 线程（编译期无法表达，运行时检查兜底）。
  - 新增 tests 模块：`#[tokio::test] sync_bridge_check_panics_on_runtime_thread`
    ——runtime 内 catch_unwind 调检查 → 必须 Err 且消息含「sync 桥接」
    （2 断言）。

## 红线

- 不做 async trait 改造（签名 ripple = 扩 scope，finding 自带轻量选项）
- 行为变更仅限「runtime 线程误调用从费解 panic/死锁变明确 panic」；
  现状全部调用路径零变化
- 不动 MemStore / 其他 block_on 站点（bot_web.rs 测试 / migration/recovery.rs
  各有独立注释，非本簇）
