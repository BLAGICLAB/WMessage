## 0. 一页结论

实机账上，子 agent 的完成率低**不是因为闸太严**，是因为三类产出被弄丢了：

| 丢在哪 | 现象 | 修法 |
|---|---|---|
| 墙钟硬杀 | 跑到一半被掐，全部正文丢失，`result_json` 写 NULL | 软墙钟收尾窗 + 硬墙钟留产 |
| 收尾格式死 | 产出完整、机检全过，只因最后一段不是 JSON 判 failed | 本地修复 + 补答一次 |
| 衔接藏真相 | 父 agent 只看到「失败」，看不到残留产出与未过项 | digest 补渲染 |

方案落在**三处**同一形态的改动上：**预算在唯一入口钳制**、**软墙钟在工具边界检查**、
**收尾契约三段修复**。全部复用既有机制（工具预算闸、收尾 JSON 解析、digest 渲染），
不引入新依赖、不引入新抽象层。

## 1. 业界口径（本轮补充调研）

上一轮（zcode 会话）已覆盖 Anthropic orchestrator-worker、OpenAI handoff、
Cognition 反方、A2A 状态机。本轮补上的是**上一轮没覆盖、但直接决定实现形态**的三条。

### 1.1 期限下传与「预留收尾预算」

gRPC 的 deadline 纪律：**下游调用继承上游的绝对期限并扣掉已用时间**，不是各用各的
默认超时；每一步开工前算 `remaining = deadline - now`，**拒绝启动剩余预算装不下的活**；
并且**为验证、落库、收尾预留一段时间**，不让最后一步把预算吃光。

> 「五个串行步骤各给 60 秒超时，看起来 1 分钟的工作流实际能占住近 5 分钟资源——
> 绝对期限才让这条链诚实。」

推论到本项目：**子 agent 的墙钟不能只是一个外层 `tokio::time::timeout`**。
超时把整条 future 掐掉时，正在跑的工具、刚说出口的话、已落盘的产物，全都悬空。

### 1.2 软顶在边界检查，不打断在飞步骤

「A budget mechanism that kills an agent mid-thought strands uncommitted work.」
软顶的形态是：**在自然接缝检查剩余预算**（迭代边界、步骤之间），检查到了就
**让模型收尾而不是硬杀**；硬墙钟只做绝对兜底。业界还明确：**重试消耗同一份预算，
不重置时钟**。

推论到本项目：软墙钟落在**工具调用边界**（dispatch 层已有的预算闸位置），
不在「跑到一半杀进程」的位置。模型收到「预算即将耗尽，停止新探索并输出收尾 JSON」
后还有一次完整 LLM 轮次产出收尾 JSON——这正是现有「工具预算触顶」闸的形状，
复用同一条路。

### 1.3 结构化输出修复是三段式，不是一段式

业界对 JSON 失败的标准处置是三步：

1. 干净解析；
2. **本地修复**（去 markdown 围栏、去尾逗号、补被截断的闭合括号）；
3. 仍失败 → 带修正提示**重试一次** LLM。

实测各家原生 structured output 的失败率：OpenAI strict 约 0.5–2%、
Claude 约 0.5–3%、本地模型 5–15%。**本地修复零 token、零延迟**，必须排在补答之前。

上一轮方案只做了第 3 步（补答），漏了第 2 步——省 token 的那一步。

### 1.4 派发契约的四要素

Anthropic 多 agent 系统的派发纪律：目标、输出格式、工具/来源指引、**任务边界**，
外加一条**溢出护栏**（少于 5 个不拆、超过 50 个不拆）。回传只回**压缩结论**，
大产物落盘传引用。

本项目已有目标 / 验收标准 / 上下文摘要三要素，缺**边界**与**力度分档**：
模型把「7 个 subtask 的调研」塞给一个子 agent，结果 600s 墙钟熔断——
这不是闸严，是任务粒度错了。

| # | 断点 | 位置 | 后果 |
|---|---|---|---|
| 1 | LLM 显式给的 `maxWallSeconds` 只钳「≥1 秒」 | `db/subagents.rs` `SubagentBudget::clamped` | 墙钟硬顶实际由调用方说了算（配置键走 30~3600，两条路两个闸） |

## 3. 改造清单

### ① 预算在唯一入口钳制（single choke point）

`SubagentBudget::clamped()` 是所有预算持久化写口（spawn / task_patch）的共同入口，
把墙钟的**上界**补上：

- 轮数：已在 `clamp_subagent_max_turns`（1..=50）钳；
- 工具数：下限 1（无上界，`MAX_FUNCTION_CALLS_CAP` 在别处）；
- **墙钟：从 `.max(1)` 改为 `clamp_subagent_max_wall_secs`（30..=3600）**——
  与配置键走同一个函数、同一组常量。

配套：spawn 回执**回显生效预算**（钳后的墙钟 / 轮数 / 工具数）。
调用方知道了才不会误判——它给的 999999 被钳到 3600，回执里写着，它就知道自己的
子 agent 最多跑一小时。

### ② 软墙钟收尾窗（边界检查 + 预留收尾预算）

- 子 agent 启动时算**绝对期限**：`deadline = running 起 + max_wall_seconds`
  （排队时间不计，与现行口径一致），放进 `SubagentSessionCtx`。
- **预留窗口**：`reserve = max(30s, 10% × 预算)`（业界默认 10%）。
- dispatch 层每次工具调用**边界**检查 `remaining = deadline - now`：
  `remaining <= reserve` → 拒绝新调用，回「预算即将耗尽：停止新探索，整理当前结果
  并输出收尾 JSON」。
- 不打断在飞工具（边界检查的语义），硬墙钟兜底。
- 模型收到拒绝后还有一次完整 LLM 轮次 → 产出收尾 JSON → 判定为成功。
- 审计事件 `subagent_wall_soft_stop`，带 `remaining` / `reserve` / `deadline`。

### ③ 墙钟熔断留产

外层 `tokio::time::timeout` 掐掉整条 future 时，已经说出口的正文随 future 一起没了。

修法不是加一个「实时正文槽」，而是**把墙钟熔断搬进模型循环**：循环在**轮边界**
检查期限，到了就带着上一轮的正文退出（与轮数熔断同款），外层 timeout 退成
绝对兜底（它只兜「单次 LLM 请求挂死」那种情况）。

理由：轮边界退出复用了既有的 `last_streamed` 快照机制，熔断正文与轮数熔断
**同一形态**；加实时正文槽则要再往 `ModelLoopDeps` 塞一个共享槽，且拿到的
是「流式碎片」而不是「最后一轮完整正文」，口径反而更碎。

墙钟熔断带自己的标记（`⏹ 已熔断（墙钟上限）`），判定时**必须排在通用熔断
标记之前**——墙钟标记包含通用标记，判反了会被认成工具调用熔断，真实原因
「墙钟触顶」又被丢掉。

### ④ 收尾契约三段修复

1. 干净解析（现有 `extract_last_json_object`）；
2. **本地修复**（新增）：尾逗号、被截断的闭合括号。string-aware，
   不做 `None`/`True` → `null`/`true` 这类替换（会改坏字符串内容）；
3. **补答一次**（新增）：仍解析不出 → 用同一份墙钟预算再发一次 LLM，
   提示「上次输出无法解析为收尾 JSON，只输出以下结构的 JSON」，拿到就用；
   仍失败才落 `result_json_unparseable`。

补答**消耗同一份墙钟，不重置时钟**（业界重试纪律）；预算已触顶的路径
（轮数 / 工具熔断）**不补答**——那不是格式问题，是预算问题。

### ⑤ digest 补渲染

- failed / budget_exceeded 行：带 `result_json.summary` 残留产出（截 300 字）；
- succeeded 行：有机检未过项时带一行「⚠️ 机检未过 N 项：<criterion>」。

纯渲染改动——父 agent 不再需要主动 `check_subagent` 深挖才知道真相。

### ⑥ 机检前缀条目派发时即验

`file_exists:` / `file_nonempty:` 后面跟的必须是**干净的相对路径**。
带空格、说明文字、绝对路径、盘符、`..` → **派发当场拒**，给出纯路径写法。
不等跑完 10 分钟才吃假阴性。

### ⑦ 提示词与 schema 减重

- 收尾 JSON：`status` + `summary` 必填，其余可选（Claude Code 的 Task tool 只要
  最终文本；A2A 把 artifacts 拆出去单挂——必填键越少，格式失败面越小）。
- 主 agent 提示词补**力度分档**（单点事实 1 个 / 对比类 2~4 个 / 复合调研先拆
  recon）与**派发边界**（一个子 agent 一个目标，别把 7 个 subtask 塞进去）。
- 派发拒绝文案带**正例**（`objective="调研 X，产出 Y，含来源"`）。

## 5. 不做清单

| 不做 | 理由 |
|---|---|
| 改成 OpenAI 式同步控制权移交 | 异步并行委派是对的（Anthropic 原文自承同步是瓶颈、异步是未来工作） |
| 子 agent 中间进度流式回传父上下文 | Cognition 反对（上下文污染）；digest + check_subagent 已够 |
| 引入 `partial_success` 第三终态 | 二值终态 + digest ⚠️ 行已覆盖语义；A2A 状态机也没有部分完成态 |
| 引入 A2A / 跨进程协议 | 单机进程内通信，YAGNI |
| 真正的 checkpoint / 断点续跑 | 残留 summary 本身就是断点信息，够用；引入存档机制是投机抽象 |
| **每个工具的超时各自继承剩余墙钟** | 深度期限下传。边界检查（②）已经挡住「剩余预算装不下的活」；工具层逐个改超时是另一套改动面，先不做，实机跑一轮再定 |
| **无输出看门狗**（idle watchdog） | 业界口径是「看输出不看时间」——长编译只要有 stdout 就不该打断。本项目工具层不向循环暴露单工具的输出流，做不了真看门狗；硬墙钟兜底 |
| LLM 重试改指数退避 + 抖动 | 次数上限 2，收益小；顺手项，等这轮实机数据再说 |

**实施中偏离方案之处**：

1. **③ 的形态从「实时正文槽」改成「墙钟熔断搬进循环轮边界」**——见 §3 ③ 的
   理由。槽位方案要往 `ModelLoopDeps` 塞共享状态，且拿到的正文口径比
   `last_streamed` 碎。
2. **② 的软墙钟多了一道闸**：dispatch 层在工具调用边界拒新调用（拒绝新工作），
   模型循环在轮边界注入一次收尾提醒（告诉模型还剩多少时间）。两道闸看的是
   同一个期限，口径同源。
3. **截断尾段多了一道语义闸**：修出来的 JSON 若认不出收尾语义（没有
   `status` / `checks`），不认——判定里「没有 status」默认按 succeeded 算，
   把「没说完」说成「说完了」。
