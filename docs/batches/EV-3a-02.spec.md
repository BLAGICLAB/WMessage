## 修法

- **finding 1**：rewrite_jsonl 改为「全量序列化到 String →
  `crate::db::paths::atomic_write(path, &contents)`」（tmp+rename，与
  api_server/api_auth 同模式）；保留 create_dir_all 前置。不加 fsync——
  仓内既有 atomic_write 语义即 tmp+rename，超出仓规的耐久性升级不自作主张。
- **finding 2**：`toggle_inner` 签名改 `Result<Option<ChangeRecord>, String>`——
  ON 返回 Some（新 append 的 cr，或 dedup 时锁内 find 到的既有记录），
  OFF 返回 None；promote 改用返回值，**删掉最终 load_changes+find 及
  误导性错误文案**。reject / evolution_toggle_proposal 忽略返回值（`?` 后
  drop），行为不变。
- 新增测试 1 个：rewrite 后无 `.tmp` 残留 + 内容正确（原子形态回归）。

## 红线

- 不动 EVOLUTION_STORE_LOCK 结构 / 锁粒度（C3-4 已定）
- 不加 fsync、不改 append_change、不动其它 commands
- promote 确认前 Rejected 预检保留（UX 守卫，语义不变）
- 行为变更仅两点：崩溃窗口消除；promote 误导性错误不可能再出现
  （并发 delete 场景现在返回锁内已写入的记录）
