# BT-05 spec — URL/host bypass 三修 + :881 转 B 类（C5-BT-05）

## 目标 findings（4 取 3；:881 转 B 类）

1. **config/io.rs:122**（high）：base_url_is_safe 手工小写 + 前缀匹配——
   `http://localhost.evil.com` / `http://127.0.0.1.evil.com` / `http://[::1].evil.com`
   全过；userinfo / 编码变体不解析。此门控决定是否提示「API Key 明文传输」，
   假阴性 = 防线失效。修：改 `url::Url::parse`（url = "2" 已在依赖）+ host 精确判定：
   https → 安全；http → host 为 localhost（大小写不敏感）或
   `host.parse::<IpAddr>().is_loopback()` 才安全；解析失败 / 其他 scheme → 不安全
   （fail-closed：原实现对畸形串同样按不安全，行为一致；「https://」裸串从
   原 true 变 false = 更严，可接受）。127.0.0.1.evil.com 不再误判（IpAddr 解析失败）。
2. **bot_web.rs:21**（high）：`unwrap_or_else(|_| reqwest::Client::new())` 降级 client
   无超时、重定向策略回默认（自动跟随）——builder 一旦失败，SSRF 防护（禁自动
   重定向）与 30s 硬超时全失效。修：降级 client 仍钉 60s 硬超时 +
   `redirect::Policy::none()` + eprintln 留痕；再失败 = expect panic（OCR 给的
   「panic loudly」选项——无约束 client 比 panic 更危险）。
3. **bot_web.rs:730**（high）：check_public_url http/https 都收 → https 首跳 302 到
   http 内网/公网 = 降级中间人（首跳 TLS 不保护后续明文跳）。修：fetch_text
   重定向循环记 prev_scheme，https→http 降级跳拒（DomainRule）；用户直接给
   http 起始 URL 行为不变（既有语义）。
4. **bot_web.rs:881**（high → **B 类攒批第 12 项**）：Jina Reader 回退把目标 URL
   发给 r.jina.ai 第三方代理且无审计。核：tools.rs:1324-1327 工具层已
   `audit_log(fetch_url | url: ...)`（URL 本身有痕），缺的是「使用了 Jina 代理」
   这一事实。补它需 fetch_text 拿到 AppHandle 或返回 used_jina 标记 =
   **签名改 + 调用链（tools.rs:1329 + 测试 3 处 block_on 直驱）**——B 类「扩 scope」，
   不自决。
