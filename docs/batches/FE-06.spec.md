## 逐条处置（原文均已核）

**实修 ① constants.ts:9-10（high）**：`execTaskDedup` 裸 Map 导出——任何 import 方可 .set/.clear；无清理契约，条目只增不剪，长会话/HMR 下无界增长。
**修法**：封装 `shouldSkip(id, now)` 单入口（窗口内重复 → true；否则记录并返回 false），内部顺带 prune 超窗条目；表本身不再导出。ripple：ChatPanel.tsx:445-451 两行 get/set 改一行 shouldSkip（注释同步）。

**实修 ② errorHandler.ts:216-220（high）**：`options.onRetry()` 裸调——重试回调同步抛错会逃出错误处理器本身。
**修法**：try/catch 包裹，catch 回收进 `handleCommandError(retryErr, ctx, { silent: true })`（silent 防 confirm 后二次弹窗）。

**实修 ③ useInlineEdit.ts:44-60（high，合并同命中 low 44-47 顺序问题）**：Enter commit 后若 input 仍在 DOM，卸载期 blur 会二次 `onCommit(draft)`（重复提交）。
**修法**：加 `committedRef`——commit() 先置位再调 onCommit；onBlur 见 committed 则跳过一次并重置（与 cancelledRef 同形态）；进入编辑态 effect 里复位。既有测试 useInlineEdit.test.tsx:129 锁旧缺陷行为（断言 onCommit 调 2 次）→ **翻断言为 1 次** + 重写注释。
（low 44-47：cancelledRef 重置先于 onCommit 的顺序依赖——committedRef 前置已覆盖同一行的顺序风险，不另改。）

**实修 ④ EvolutionPanel.tsx:149-158（high）**：`ACTIVE_STATUSES.has(c.status as string)` cast 绕过编译期检查，status 字面量改名/增删会静默漂移 toggle 判定。
**修法**：`const ACTIVE_STATUSES: ReadonlySet<ChangeRecord["status"]> = new Set([...])`，用法去 cast（types.ts 的 ChangeStatus 未导出，经 ChangeRecord["status"] 索引取用，不动 types.ts 导出面——knip 安全）。

**FP ⑤ types.ts:5-6（high → FP）**：finding 称 `args?: string`「迫使每个 consumer JSON.parse」。**核后**：唯一 consumer（ChatPanel.tsx:1141-1145）只做 length/slice 文本渲染，无人 JSON.parse；producer（:357-360 SSE payload）拿到的本就是序列化字符串。string 是端到端诚实类型，改 Record 反而要无谓 stringify。前提错误，零代码处置（reviewer pass 后才可标）。

**转 B 类 ⑥ ChatPanel.tsx:416-433（high → B 类 #22）**：围观执行会话期间 busyRef 不锁，用户可 Send 与 bot_execute_task 并发同会话（响应交错 + 收尾 reload 冲掉输入）。**方向抉择**：A=finding 原方案全 busy 锁（堵发送但也堵 switchSession/newSession/deleteSession——用户被困在围观页直到执行完）；B=专用 execWatchRef 只拦 Send（切换会话自由）；C=维持现状（先核后端 bot_chat 同会话并发是否自有防重入）。既有注释约定「执行本身不吃 busy 锁（会话隔离天然并发）」，A/B 都触碰该约定的解读 → 攒批报人拍。
