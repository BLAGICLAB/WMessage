# Batch Spec: AP-05

## 目的

修 C5-AP-05 全簇 3 条（持锁跨 I/O）：handlers.rs create_task:277 / update_task:405 / delete_task:561——锁内直接 `req.respond`/`internal_err`/`upsert_err`，慢/断开客户端把 API_RMW_LOCK 带过 socket I/O，串行化全部并发 API 写。统一改「锁内算 Result、出锁后响应」。

## 人类可读摘要

- family: lock-held-across-io
- 覆盖 findings: 3（C5-AP-05 全簇）
- 预估 diff: 1 file / +60/-30 lines（B 类结构性，budget 预留 ~40% = +85/-45）
- OCR 计划: r1, timeout 1800s, 期望 comments ≤ 5

## 核实的编译层事实（spec 前已核）

1. 三处同型：`let t = { let _rmw = API_RMW_LOCK.lock()...; ...错误分支直接
   internal_err(req,...)/req.respond(...) + return ... }`——响应 I/O 在锁内。
2. `internal_err`/`upsert_err`（util.rs:61/:71）按值消费 `req` → 锁内块不能
   直接持有 req；修法 = 锁内块（IIFE 闭包，拿 `?` 便利）返回
   `Result<Task, 本地 Err 枚举>`，出锁后 match 分流响应。
3. 每函数本地枚举只含该函数实产变体（create=Load/Upsert；update=Load/
   NotFound/Upsert；delete=Load/NotFound/Upsert/AlreadyDeleted），
   无 unreachable 臂。
4. 行为保持：状态码 / 响应体 / after_change 时机（成功路径本就出锁后）
   / delete 幂等重删 200 不 after_change（OCR 自认 fine，不动）全不变。
   唯一行为变更：错误/404/幂等 200 路径不再持锁跨 I/O。
5. 测试：handlers.rs 无内联测试（0 assert），HTTP 级覆盖在 mod.rs
   （create/update/delete/404/409 冲突路径已有）。纯结构性重排，
   **不加新测试**；assertions_min 省略（对照 AP-04 sse.rs 先例）。
6. after_change（SSE fanout）本就在锁外（:400-402 注释），不受影响。

## 红线

- family 一致性：只含 lock-held-across-io 三处同型
- 行为等价：响应码/响应体/审计日志/after_change 时机逐项不变
- 不动 util.rs（internal_err/upsert_err 签名不变）

## spec 起草后自查三条

1. `expected_files` = 1：src-tauri/src/api_handlers/handlers.rs。无签名变更
   （三 fn 私有、签名不动），无 caller ripple，无新文件。
2. budget = **B 类**（三个持锁块整体重组为闭包+match）。整块估：
   create +14/-8；update +18/-10；delete +20/-12；注释 +8；
   计 +60/-30，预留 numstat 偏低 ~40% → **max +85/-45**。
3. findings 逐条 fix 字段列明改法与 ripple（无 ripple，同文件内）。
