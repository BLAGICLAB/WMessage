# 文件编辑最佳实践（file-edit-best-practice）

> 安装方式：把本目录放进 WMessage 数据目录的技能目录（设置页技能面板可见）。
> 适用场景：用 edit_file / write_file 修改代码或配置文件。复杂编辑任务先读本技能。

## 为什么总失败：两大原因与对策

编辑失败的头号原因是**搜索段（oldString）与原文有差异**，二号原因是**命中多处**。
对策只有一条纪律：**先读后改**——edit_file 之前必须 read_text_file 看过原文，
oldString 从你实际读到的内容里复制，不要凭记忆或想象拼写。

## edit_file 纪律

1. **oldString 从 read_text_file 的输出里逐字复制**（含缩进）。工具对行尾空白与
   CRLF 自动容错，但**缩进必须一致**。
2. **oldString 要唯一**：只给一行 `return 1;` 如果文件里有多处会报「N 处命中」。
   锚点技巧：带上函数签名行 + 调用点行（前后各 1-2 行）使命中唯一。
3. **newString 保持原文件风格**：缩进层级、换行符、命名风格与上下文一致；
   行尾不要带多余空白。
4. **大改拆小步**：一次 edit_file 只做一处逻辑变更；连续多次小 edit 比一次
   巨型替换可靠得多（失败定位也精确）。
5. **改完验证闭环**：改完用 read_text_file 复核改动区域；能跑测试就跑测试
   （run_python 或让用户跑），把结果写进回复。

## write_file 纪律

1. **只用于新建文件**；改已有文件一律 edit_file（覆盖会弹窗打扰用户，且丢原文）。
2. 写之前想清楚完整内容再调用——工具一次写入整个文件，不支持追加。
3. 路径必须在可写目录（AI_Gen_Files / 任务卡绑定文件夹 / 设置页 allowedDirs）。

## 失败了怎么办

- 报「未找到」→ 先 read_text_file 确认原文（注意缩进），重新复制 oldString。
- 报「N 处命中」→ oldString 加上下文行，让锚点唯一。
- 报「写回失败」→ 文件可能被外部程序占用，稍后重试或换路径。
- 同一文件连续失败 2 次 → 用 record_lesson 记一条教训（scenario 填 edit_file）。
