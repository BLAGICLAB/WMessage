## 2. 场景一：手动任务卡执行透明 ⭐ 核心链路（P1/P2）

**准备**：新建任务卡「写一首诗并保存到文件」→ 卡上 🤖 交给机器人（模型会调 create_task/
write_file 类工具）。

- [ ] ⭐ **执行会话围观**：点「交给机器人」→ 自动切到挂件新会话（📋 前缀），流式输出可见
- [ ] ⭐ **工具徽章增强（P2-b）**：聊天里的工具行不再只有名字——每个工具 pill 带状态色
      （成功 ✓ 绿 / 失败 ✕ 红）；点开「进程 N/M」折叠 → 每个工具有**入参 + 结果文本 + 耗时**
- [ ] ⭐ **文件摘要带 ±行**：回复完成后消息底部出现文件 pill，带 **+N −M** 行数统计
      （结构化 `bot-file-changed` 数据，非正则猜测）
- [ ] ⭐ **任务卡「执行详情」**：执行完成后，主窗口该任务卡出现「执行详情」按钮（🤖 旁）→
      点击打开弹层：
  - [ ] 摘要头：状态「完成」+ 耗时 + N 轮 · N 次工具 · N 个文件 + tokens 数
  - [ ] **文件修改区**：文件行带 ±行数 → 点「查看 diff」→ **红绿着色的 unified diff**
  - [ ] **工具时间线**：每次调用一行（绿/灰点 = 成败、第 N 轮、耗时），展开看入参/结果全文
- [ ] ⭐ **全程不翻 bot.log**：以上信息全部来自界面（总验收标准 ①）

## 3. 场景二：定时任务执行透明 ⭐（P2-c）

- [ ] ⭐ **定时执行可见**：定时任务页新建 at: 作业（内容随便写、时间 +2 分钟）→ 到点后
      行内出现**「执行中…」徽标**（此前执行中完全不可见）
- [ ] ⭐ **执行历史双跳转**：完成后展开该作业「历史」→ 最新一行有「**痕迹**」和「**会话**」
      两个按钮 →「痕迹」打开该次执行详情；「会话」跳挂件围观 ⏰ 执行会话
- [ ] **收尾刷新**：执行完成后列表「上次/成功/失败」徽标自动刷新（无需手动刷新页面）

## 4. 场景三：工作流执行透明 ⭐（P2-c）

**准备**：新建工作流 3 节点串联，其中中间节点绑定一个必失败任务（如让机器人读一个
不存在的文件并「必须成功返回内容」）。

- [ ] ⭐ **实时高亮**：开始执行 → 正在跑的节点**蓝色描边 + 脉冲动画**（不再只靠 5s 轮询变蓝）
- [ ] ⭐ **失败区分**：失败节点**红环**；其下游节点**灰环半透明**（skipped，与真失败区分）
      → note 前缀「⏭ 因上游…失败未执行」照旧
- [ ] ⭐ **节点痕迹入口**：任意节点左上角 🕘 按钮 → 打开该节点执行的详情（时间线 + diff）
- [ ] **当前进度**：总目标卡 ✔ N/M 照旧；无关分支照常执行（失败传播语义不回归）

## 5. TracePanel 深度功能（P2-a / P4A）

**准备**：用 §2 的任务卡（有文件修改的执行）。

- [ ] ⭐ **回滚成功**：执行详情 → 文件行「回滚」按钮 → 文件内容恢复到 AI 修改前
      （弹层内提示「已回滚」；磁盘文件核实）；回滚后详情自动刷新
- [ ] ⭐ **回滚漂移闸**：先**手动编辑**该文件保存 → 再点「回滚」→ 被拒绝并提示
      「文件自本次修改后已被改动（指纹不符），拒绝回滚以免吞掉后续修改」
- [ ] **多次执行切换**：同一张卡再跑一次 → 执行详情顶部出现多个时间 pill，可切换查看各次
- [ ] ⭐ **JSONL 导出**：详情头部「导出」→ 显示路径（`$DATA/exports/trace-<id>.jsonl`）→
      打开文件确认首行 trace 摘要 + 后续 span/file_change 行（type 字段区分）
- [ ] **新建文件不可回滚**：kind=create 的文件行没有「回滚」按钮（create 撤销=删文件，
      危险动作暂不支持——预期行为）

## 6. 参数透明（P3-a/b）⭐

- [ ] ⭐ **参数卡可见**：设置 → 机器人 → 「Agent 运行参数」卡：7 项输入（循环轮数/历史预算/
      子 agent 三预算/搜索条数/工具截断），placeholder 显默认值，悬停有调参说明
- [ ] ⭐ **参数生效**：`maxRounds` 改成 **3** → 保存 → 执行一张复杂任务卡 → 第 3 轮后模型
      收到熔断收尾（聊天可见「已熔断」类文案）；改回 50
- [ ] **钳制角标**：`maxRounds` 填 9999 → 保存 → 重新打开设置页值被钳到 **200**
      （后端 clamp；历史预算同理钳 20000–500000）
- [ ] ⭐ **词元统计实装**：设置 → 词元统计（原「规划中」占位）→ 汇总四格（输入/输出 tokens、
      执行次数、工具调用）+ 按日双色条形（浅=输入 深=输出）；点「刷新」重拉
- [ ] ** Profiles 三预设（P4B）**：参数卡顶部「保守/标准/放开」→ 点「放开」→ 授权模式变
      auto、轮数 200、熔断 300、py 超时 300 全部落盘（重新打开设置页核对）；点「标准」回默认
- [ ] **上下文水位条（P4B，Anthropic 协议）**：切到 Anthropic 模型（条目 contextK 已填，
      如 200）→ 聊几轮 → 输入栏上方出现「Σ N.NK」+ 百分比进度条；≥80% 变红提示 /compact
  - ➖ OpenAI 协议模型无此条（流式 usage 需 stream_options，网关兼容风险留档——预期局限）

## 7. 授权升级（P3-c）⭐

- [ ] ⭐ **四档按钮**：设置 → 机器人 → 授权模式出现第 4 档「**白名单内自动**」；挂件输入栏
      授权 pill 出现「自动」
- [ ] ⭐ **auto 档无人值守**：切到 auto → 定时任务写一个 AI_Gen_Files 内的文件 →
      **全程无确认窗**、执行成功（ask 档后台写文件类任务必失败的黑盒痛点就此消除）
- [ ] **auto 覆盖写免确认**：auto 档让 agent `write_file` 覆盖一个已存在文件 → 不弹覆盖确认
      直接成功；切回 ask 档同样操作 → 弹确认（yolo 档维持既有弹窗行为）
- [ ] ⭐ **deny 规则**：设置 → 机器人 → 工具权限规则表 → 添加 `run_python` = **deny** → 保存 →
      挂件聊天「用 Python 算一下 1+1」→ 模型回复「已被工具规则禁用」类文案且实际未执行
- [ ] **ask 规则**：改 `edit_file` = **ask** → 让 agent 改白名单内文件 → 仍弹确认
      （规则优先于授权模式——白名单内本来放行也被规则拦下确认）
- [ ] **规则清洗**：规则表填一个工具名留空 / 删掉 action → 保存 → 重新打开被清洗掉
      （非法项不入库）

## 8. 活动页与痕迹治理（P4A/B）

- [ ] ⭐ **活动聚合页**：左导航「活动」（工作流/定时任务之下）→ 最近执行列表
      （时间/标题/来源徽标/状态/耗时/tokens），手动/定时/工作流混合呈现
- [ ] **running 实时**：执行一张任务卡期间打开活动页 → 该行「执行中」脉冲动画，收尾自动更新
- [ ] ⭐ **痕迹清理**：设置 → 数据管理 → 「执行痕迹」卡 → 保留天数填 0 以外的值（如 30）→
      「清理」→ 提示「已清理 N 条」或「没有需要清理的痕迹」；任务数据不受影响

## 9. bot.log 审计抽查（开发者视角，可选）

```bash
grep -E "trace\.(start|complete|span_overflow)|file\.(change|rollback)|tool_rule\.hit|tool\.output\.truncated|trace\.export" \
  "$DATA/bot.log" | tail -30
```

- [ ] **trace.start / trace.complete**：每次任务卡执行各一条（complete 带 turns/tools/files/tokens/ms）
- [ ] **file.change**：每次 AI 文件落盘一条（path/kind/±行）
- [ ] **file.rollback**：§5 回滚操作一条（Warn 级）
- [ ] **tool_rule.hit**：§7 deny/ask 规则命中各一条
- [ ] **tool.output.truncated**：§6 截断验证时一条（如做过）——span 里存的是原文
      （TracePanel 展开结果可见全文，模型收到的是截断版——两者并存是设计行为）
