# Batch Spec: SC-05

## 目的

修 scripts 域「hook 覆盖不全」簇：test-fast.sh:56 步骤 0 审计批次号防线只扫 `git diff --cached` / `git diff`，**untracked 新文件不在任何 diff 里**——新增未 add 的 .rs/.ts/.tsx 含禁入批次号可整体绕过防线（下游 NEED_CARGO/NEED_TS 判定却早就含 untracked，防线与下游口径不一致）。

## 人类可读摘要

- family: hook-coverage（与 HOOK-1/HOOK-2 同根因家族：门禁覆盖口径不全）
- 覆盖 findings: 1（实修）
- 预估 diff: 1 file / +12/-4 lines
- OCR 计划: r1, timeout 1800s, 期望 comments ≤ 0（scripts/** 被 exclude）

## finding 原文核实

**test-fast.sh:56（high，真）**：步骤 0 只扫 `git diff --cached` 和 `git diff`，两者都不含 untracked 文件；新写的含禁入批次号的源文件不 add 就能滑过审计门。
**修法**：把 untracked 的 .rs/.ts/.tsx **全文**并入「待扫新增行」流，与 diff 新增行走同一套 `audit-ok` 豁免 + 批次号正则：

```bash
NEW_LINES=$(echo "$DIFF_SRC" | grep '^+' | grep -v '^+++' || true)
# untracked 新文件不进任何 diff——扫全文，与 diff 新增行同规（-z 防空格路径被引号包裹漏读）
while IFS= read -r -d '' f; do
    if [[ -f "$f" ]]; then
        NEW_LINES="$NEW_LINES
$(cat "$f")"
    fi
done < <(git ls-files -z --others --exclude-standard -- '*.rs' '*.ts' '*.tsx' 2>/dev/null)
BAD_LINES=$(echo "$NEW_LINES" | grep -v 'audit-ok' | grep -E '<同前正则>' || true)
```

同步 :53 段注释与顶部 docblock [0/N] 行说明口径变为「diff 新增行 + untracked 全文」。

**B 类判定：非 B 类。** 理由：不改既有约定（禁入模式、audit-ok 豁免原样），只是把防线覆盖口径补齐到与下游 NEED_* 判定一致——属于既定意图的执行漏洞修复，不是方向变更。

## 验证方式

直接在本仓库跑 test-fast.sh 的步骤 0 路径（构造不触发 NEED_* 的根目录 `*.rs` untracked 文件，避免拉起 cargo/vitest 长链路）：

1. untracked 坏文件（含 `批次99审计`）→ 期望步骤 0 拒，exit 1
2. untracked 坏内容但带 `audit-ok` → 期望放行
3. untracked 干净文件 → 期望步骤 0 过
4. 测后删除临时文件，工作树复原
