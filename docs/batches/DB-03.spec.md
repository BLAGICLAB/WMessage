## 核实的编译层事实（spec 前已核）

1. **mod.rs:61（实修）**：`open_db` 的 legacy 拷贝段（:61-82）
   `!db_path.exists()` → `legacy_db.exists()` → `copy_legacy_db` 三步无同步；
   并发 open_db（首装多线程/多命令并发）可同时过检查竞态拷贝 → 半成品
   db/-wal/-shm 三元组。修法：`static LEGACY_COPY_LOCK: Mutex<()>` +
   锁内双检 `!db_path.exists()`（后到者跳过）——照 BOT_ASSIGNED_RESET_DONE /
   DB_WRITE_LOCK 同文件先例；锁仅护首装一次性窗口，常态零代价
   （外层 exists 不进锁）。`copy_legacy_db`（paths.rs:51）不动。
2. **tasks.rs:396（FP 判定）**：finding 核心断言「load_all 把多行读跑成
   多条独立语句，并发 upsert 可插入其间」**不实**——`load_all`
   （tasks.rs:286-318）是**单条 SELECT**（subtasks/files 为同行 JSON 列），
   单语句在 SQLite 任何 journal 模式下都是快照一致的（WAL 下读快照；
   rollback 模式下 SHARED 锁挡住写者）。db_load_for 交给前端的快照
   只来自这一条 SELECT。finding 建议的 transaction 包装解决的是不存在的
   撕裂。**判 FP**（前提与实现不符，BT-02/BT-06/BT-07b 同处理）——
   记录 + 不改。**high 判 FP 触发 reviewer 独立核验**（批后随抽查执行）。
3. db/mod.rs 现有 151 asserts，既有 copy_legacy_db / pragma 测试覆盖
   拷贝正确性；锁+双检为模式复用（同 DB_WRITE_LOCK），竞态测试需
   mock AppHandle 并发首装（全局态 + 路径不可控，flaky）——**不加新测试**，
   spec 声明。
4. assertions_min：mod.rs = 151（不变，防削弱）。
