### ACC-C-01 · 侧边磁吸挂件窗口整体退役

- **SPEC**：2-22
- **层级**：L2 实机
- **历史卡**：—（无：全库无实机卡）
- **前置**：应用已启动；左导航渲染完成；鼠标可自由移到屏幕左右边缘
- **步骤**：
  1. 启动应用，确认左导航渲染完成（首页可见）。
  2. 鼠标移到屏幕最左边缘中部静止 5 秒；再移到最右边缘中部静止 5 秒；然后沿边缘缓慢拖动一遍。
  3. 打开左导航，从上到下读完所有分组标题与条目名。
  4. 点左导航「聊天」，看聊天是主内容区整页还是独立浮窗；再看系统窗口列表（macOS：窗口菜单 / 台前调度）里本应用的窗口数。
- **判据**：
  1. 【可观测】步骤 2 全程屏幕上没有出现磁吸挂件窗口：无收起态商标方块、无边缘吸附动画、无浮层遮住主窗口边缘。
  2. 【可观测】左导航只有两个分组标题——「任务卡」与「Agent能力」；「Agent能力」组下依次是「聊天 / 定时 / 程序 / 活动 / 通知」，全导航无「挂件」「侧边」「磁吸」条目。
  3. 【可观测】点「聊天」后聊天占满主内容区；系统窗口列表里本应用只有 1 个窗口（主窗口），聊天不是第二个独立窗口。
  4. 【可核对】`grep -rn "WebviewWindowBuilder" src-tauri/src/` 只命中 `src-tauri/src/lib.rs` 一处（主窗口构造），源码里没有第二处窗口构造。
  5. 【可核对】`grep -rni "widget\|magnet\|磁吸" src-tauri/src/ src/` 无命中——挂件机制的事件名、组件名、窗口标识均已从代码里删净。
- **证据**：截图（屏幕左右边缘各 1 张，证明无浮窗）+ 左导航全貌截图 + 两条 grep 的终端输出
- **失败处置**：本卡无审计事件，改用源码检索分家——`grep -rn "WebviewWindowBuilder" src-tauri/src/` 多出第二处 = 挂件复活（判失败）；仍只有一处但机器上看到了浮窗 = 应用侧回归，开缺陷单
- **缺口补验**：负向卡：侧边磁吸挂件窗口不得复活

### ACC-C-03 · 聊天常挂载：切视图只切可见性不卸载

- **SPEC**：2-24
- **层级**：L1+L2（L1 自动化 + L2 实机）
- **历史卡**：M91、M92（`docs/realmachine-smoke-test-2026-10-25.md`）
- **前置**：应用已启动；机器人总开关已打开；模型可用；至少有一个会话
- **步骤**：
  1. 进「聊天」，发一条需要较长生成的消息（如「列出当前目录下的文件」）。
  2. 确认流式已经开始后，立刻点左导航「任务」。
  3. 等机器人这一轮回复结束（此时看不到聊天区，通过任务卡 🤖 按钮与右侧栏确认任务已收尾）。
  4. 点回「聊天」。
  5. 再来一轮：发消息 → 切到「任务」→ 在任务页触发一次子 agent 或定时任务 → 切回「聊天」。
- **判据**：
  1. 【可观测】步骤 4 切回聊天后，刚才那条助手回复的正文完整在原会话里（不消失、不只剩用户消息、不回到空态）。
  2. 【可观测】切回后消息顺序与发送顺序一致，没有出现「回复在别处完成、这边还是旧内容」的错位。
  3. 【可观测】步骤 5 切走期间触发的子 agent / 定时任务，切回聊天后在右侧栏「子 Agent」工作面能看到终态行（不空、不永远转圈）。
  4. 【可核对】`grep -rn "chat-focus-session\|chat-open-session\|execute-task\|subagent-finished" src/components/ChatPanel/` 四个监听器均在 ChatPanel 内部注册。
  5. 【可核对】`grep -n "view === \"chat\" ? \"h-full\" : \"hidden\"" src/App.tsx` 命中——ChatPanel 用可见性切换而非条件渲染卸载。
- **证据**：截图（切走前 / 切回后同一会话的同一屏）+ 录屏（流式中切页再切回）
- **失败处置**：先分清「应用坏了」还是「卡片过期」——用 `grep -F "<事件名>" src-tauri/src` 确认事件名还在源码里（本卡无审计事件，改查 `grep -rn "chat-focus-session" src/components/ChatPanel/`：监听器不在 = 卡片过期）
- **缺口补验**：execute-task / chat-focus-session / subagent-finished 三监听器在切走页面期间的行为未验

### ACC-C-04 · 聊天窗滚动语义：贴底才跟随

- **SPEC**：2-25
- **层级**：L1+L2（L1 自动化 + L2 实机）
- **历史卡**：—（无：全库无实机卡）
- **前置**：应用已启动；机器人总开关已打开；当前会话里已有 ≥3 屏历史（用于能往上翻）
- **步骤**：
  1. 滚到消息区最底部，发一条长回复，等流式开始。
  2. 流式进行中把消息区向上拖到离底明显超过 32px（截图记录视口位置），此后不再碰滚轮。
  3. 等这一轮回复结束，观察末条消息是否仍停在视口下方。
  4. 把消息区拖回底部，等下一条增量到达。
  5. 切到左导航「任务」再点回「聊天」。
  6. 另开一轮，让机器人中途报错或用 /stop 中断。
- **判据**：
  1. 【可观测】步骤 2 之后：后续流式增量不把视口拽回底部，视口停在原处，读到的首行内容不随增量变化。
  2. 【可观测】步骤 4 把视口拖到底（离底 ≤32px）后，下一条增量到达时视口重新跟随到底部（末条消息底部始终可见）。
  3. 【可观测】发新消息或切换到另一个会话后，视口立即复位到底部（末条消息完整可见，不用手动下滑）。
  4. 【可观测】步骤 5 切走再切回后，视口在底部，不是上次停留的位置。
  5. 【可观测】步骤 6 报错/中断时，已流出的正文整段保留在消息流里，错误提示接在正文后面（正文没有整段凭空消失）。
  6. 【可核对】`grep -n "STICK_BOTTOM_PX" src/components/ChatPanel/constants.ts` 值为 32。
- **证据**：截图（离底状态 / 贴底状态各一张，带滚动条位置）+ 录屏
- **失败处置**：先分清「应用坏了」还是「卡片过期」——用 `grep -F "<事件名>" src-tauri/src` 确认事件名还在源码里（本卡无审计事件，改查 `grep -n "STICK_BOTTOM_PX" src/components/ChatPanel/constants.ts`：常量被改 = 卡片过期）
- **缺口补验**：无实机卡：贴底 32px 判据、滚回底恢复跟随未验

### ACC-C-05 · 在途回合不丢：回合开始即落库

- **SPEC**：2-26
- **层级**：L1+L2（L1 自动化 + L2 实机）
- **历史卡**：M18、M19（`docs/realmachine-mutation-test-2026-10-23.md`）、S33（`docs/realmachine-regression-test.md`）
- **前置**：应用已启动；机器人总开关已打开；模型可用；已有一个会话
- **步骤**：
  1. 在会话里发一条消息，盯着消息流看用户气泡何时出现。
  2. 机器人还在回复时切到左导航「任务」，等回复结束。
  3. 点回「聊天」，看该会话。
  4. 在回复进行中刷新窗口（macOS：⌘R，或开发者工具 Reload），回到同一会话。
- **判据**：
  1. 【可观测】步骤 1：用户消息气泡在机器人整轮回复结束之前就出现在消息流里（不等到收尾才落库）。
  2. 【可观测】步骤 3：该会话里用户消息与助手回复都在，顺序不变；助手侧不是空占位气泡。
  3. 【可观测】步骤 4 刷新后：同一轮的助手回复正文仍在（不是只剩用户消息那一半），且与刷新前逐字一致。
  4. 【可观测】刷新后没有出现同一段正文重复两遍（残缺视图被整段写回库的老问题不复现）。
  5. 【可核对】`grep -rn "bot_history_save" src-tauri/src/` 命中——回合开始即落库、回合收尾再写最终态，库里始终是这一轮的真源。
- **证据**：截图（切走前 / 切回后 / 刷新后同一会话）+ `<data_dir>/bot.log` 片段
- **失败处置**：先分清「应用坏了」还是「卡片过期」——用 `grep -F "<事件名>" src-tauri/src` 确认事件名还在源码里（`chat.history_truncated` / `chat.history_save_truncated` 是历史截断事件，只在历史超限时出现；它不出现不等于本卡失败）
- **缺口补验**：—

### ACC-C-08 · 托盘菜单「打开主窗口 / 打开聊天 / 退出」

- **SPEC**：2-29
- **层级**：L2 实机
- **历史卡**：S20（`docs/realmachine-regression-test.md`；该卡实为「停止回显『已停 N 条』+ 本地提示不落库」，与本条只算间接相关）
- **前置**：应用已启动且主窗口可见；另开一个别的应用窗口盖在 wmessage 主窗口上（用来验「推到最顶层」）
- **步骤**：
  1. 点主窗口关闭键（应隐藏而非退出），确认主窗口消失但托盘图标还在、进程未退。
  2. 托盘图标右键 → 读菜单项。
  3. 点「打开聊天」。
  4. 再点一次「打开聊天」。
  5. 托盘右键 → 「退出」。
- **判据**：
  1. 【可观测】步骤 1：主窗口关闭后应用仍在运行（托盘图标在、进程未退），符合「关闭=隐藏、托盘常驻」。
  2. 【可观测】步骤 2：托盘右键菜单恰好三项——「打开主窗口」「打开聊天」「退出」，顺序一致，没有第四项。
  3. 【可观测】步骤 3：主窗口被推到最前（可见且盖在别的应用窗口之上），同时切到聊天页。
  4. 【可观测】步骤 4：再点「打开聊天」不叠出第二个窗口，窗口数不变。
  5. 【可观测】步骤 4：点「打开聊天」不切走当前会话（空载荷只切视图）。
