# BUG-002 — `Default::default()` 后逐字段赋值(测试反模式)

## 位置
`src-tauri/src/bot_skills/runtime.rs:670, 678, 689`(clippy `field assignment outside of initializer`)

3 处全在 `#[cfg(test)] mod tests` 内,3 个测试函数:`preflight_rejects_disabled` / `preflight_rejects_blacklist_intent` / `preflight_passes_normal`

## 严重度
**S3**(design — 测试代码风格,无功能影响)

## 类别
clippy `field_reassign_with_default`

## 复现步骤
```bash
cd src-tauri
cargo clippy --tests -- -W clippy::field_reassign_with_default 2>&1 | rg "field_reassign_with_default|bot_skills/runtime.rs"
```
输出(修复前):
```
warning: field assignment outside of initializer for an instance created with Default::default()
   --> src/bot_skills/runtime.rs:670:9
   --> src/bot_skills/runtime.rs:678:9
   --> src/bot_skills/runtime.rs:689:9
```

## 根因
3 个测试用 `SkillMeta::default()` + 逐字段赋值,而非 struct literal 初始化。`SkillMeta` 有 11 个字段(`name`/`description`/`risk_level`/`mode`/`max_steps`/`timeout_secs`/`rollback`/`enabled`/`resumable`/`intents`/`max_rounds`),用 `..Default::default()` 一次性填默认比逐字段写更紧凑、更不易遗漏。

## 修复方案
改 struct literal 初始化(用 `..Default::default()` 填未显式设置的字段):

```rust
// 修复前
let mut m = SkillMeta::default();
m.name = "x".into();
m.enabled = false;

// 修复后
let m = SkillMeta {
    name: "x".into(),
    enabled: false,
    ..Default::default()
};
```

`preflight_rejects_blacklist_intent` 因为后续还要 `m.description = ...` 二次赋值,保留 `let mut` 但用 struct literal 初始化 `name`:
```rust
let mut m = SkillMeta {
    name: "x".into(),
    ..Default::default()
};
m.description = "批量删除所有任务".into();  // 后续 mutation 保留,不属于 default-then-assign 反模式
```
