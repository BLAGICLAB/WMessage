定时模块 · 提醒怎么分组

2026-11-10 · 设计小样 · 结论：标签切换，不用分页

提醒与定时作业是同一条 30s tick 上的两条并列链路：作业到点做事（建卡交机器人执行）， 提醒到点说话（发一条系统通知）。两者共用同一套定时串格式，存储与触发路径各走各的。 放进同一个「定时」模块时，问题只有一个：怎么把这两类分开给用户看。
结论是顶部标签切换（定时任务 / 提醒，各带计数），不用分页、不用分区列表、不用混排。 下面先给四个候选的取舍，再给推荐稿的高保真。

暗色 亮色

一、四个候选 分组形态

为什么不是分页：本仓的 pagination 已有固定语义——PoolPager 的 8 页是 「本周 7 天 + 未排期池」，翻页 = 换时间段。拿它切「作业 / 提醒」会让用户误以为在按时间翻， 而这两类之间没有时间关系。而且两类各自的量级是「个位数到十几条」，翻页的成本远高于一次点击。 结论：分页在这个模块里是错误控件。

A · 顶部标签切换 推荐

定时任务 6提醒 3

两类互斥、各带一套操作，各自规模小 → 一次点击切视角。 代价：提醒不在当前屏时看不见 → 用标签上的计数兜住（3 条提醒不会被忘）。

B · 分区列表（同屏两段）

定时任务
提醒

一屏看全两类，不用来回切。 代价：下半段像"附录"；两类行的操作按钮不同（作业有「立即执行/历史」，提醒没有）， 同屏出现两套按钮语义 = 噪音。

C · 混排一行一徽标

按下次时间排成一条时间线，"接下来会发生什么"。 代价：行模板必须按类型分叉（提醒无「执行中/历史/预演/痕迹」）， 一行要在两种按钮集之间切换；顶部「最近将执行」摘要也失去单一含义。

D · 分页 否决

‹1 / 2›

翻页看下一批。 代价：与本仓 pagination 的既有语义（换时间段）冲突，用户会误读成"翻到明天"； 十几条量级用不上翻页，还多一次点击才能知道另一边有什么。

二、推荐稿 高保真 · 可点击

沿用 SchedulePage 现有结构（标题 + 新建按钮 + 摘要条 + nm-card 行）， 只在标题与列表之间插入一行标签，并把行模板按 kind 分叉。 标签配方照 NotificationsPage 的 role=tablist（选中态 = 凹陷）， 计数用 <span class="n">，与仓库已有两处先例一致（通知页「待处理/全部」、程序页「运行/版本」）。
一处措辞选择：导航项已叫「定时」，所以页标题从「定时任务」改回「定时」， 两个标签才叫「定时任务 / 提醒」——否则页面上「定时任务」会同时出现在标题和标签里。 想零改动也行：标题留「定时任务」，第一个标签改叫「自动执行」（但「自动执行」已是执行档的名，会撞）。

暂停/恢复 · 修改 · 取消
  • 一次性提醒（at:）不显示「暂停」——它触发即删，没有下次可暂停；周期提醒才有。行模板要按 oneShot 再分一次叉，这是「两类不能混排」的具体代价。
  • 提醒行没有「立即执行」：提醒不做任何事，没有"试跑"这回事。也没有预演档——预演是给「到点做事」用的中间态，提醒没有事可预演。
  • 没有执行历史：提醒不执行，没有 run 记录；只有「已触发 N 次」这一个计数。
  • 「已触发 N 次」是新出口：firedCount 早就落库了，但没有出口——提醒行是它第一次有地方显示。

四、控件复用 0 新组件

提醒的重复档与作业的定时档逐档同构——提醒的 repeat（none/daily/weekly/monthly） 与作业的 schedule（at:/daily:/weekly:/monthly:）是同一套定时串格式， ScheduleEditorPanel 的四档按钮直接可用，只需换 preview 文案。

作业 到点做事

每天 09:00，到点自动新建任务卡并交给机器人执行

额外两个旋钮：失败重试 / 失败自动暂停——作业会失败，提醒不会。

提醒 到点说话

每天 11:00，到点发一条系统通知提醒你（只说话，不做事）

去掉两个失败旋钮——提醒没有执行，就没有失败。preview 是唯一必须改的文案。

五、落地要点 实现清单

  • 后端补 enabled 写路径：新增 reminder_set_enabled——reminders.enabled 列已存在、load_due_reminders 已按它过滤、list_reminders 已渲染「已暂停」，但没有任何写路径能把它置 false（插入恒为 None）。这才是真洞：周期提醒今天无法暂停。
  • 概览命令追加提醒条目：schedule_overview 现在只回 kind="job"；追加 kind="reminder"（load_reminders 已存在，一行查询）。
  • kind 分支沿用既有写法：前端 ScheduleEntry.kind 现为字面量 "job"，放宽成 "job" | "reminder"；行模板按 kind 分支（页面里已有 e.kind === "job" 的分叉先例）。
  • 提醒的编辑/新建：复用 ScheduleEditorPanel，新面板只换 preview 文案与去掉两个失败旋钮；后端补 reminder_update（改内容/时间）与 reminder_create（前端建提醒）——目前提醒只有工具能建。
  • 不新建导航项：不触发 SPEC 新功能条目 + 验收卡 + 追踪矩阵的全套改动。
  • 顺带：list_reminders 工具仍在（聊天里问也能答），两者共用同一张表，不构成两个真相源。
