# BT-11 spec — HTML 解析前缀误中：开标签精确匹配（C5-BT-11 全簇 2 条）

## 背景核

`first_between`（bot_web.rs:421）与 `first_open_tag`（:431）用 `str::find("<a")`
前缀匹配开标签——`<a` 会误中 `<abbr>`/`<address>`/`<area>` 等同前缀标签，
h2/h3 块内前置 `<abbr>` 时标题与链接来自不同 DOM 节点。调用点 5 处全在
parse_bing/parse_baidu（:640/:643/:646/:654/:673/:685），签名不变内部换实现。

## 目标 findings（2 条实修，同根同文件）

- **bot_web.rs:412 + :422**（同根合并修）：新增 `find_tag_open(s, pat)`——扫描
  全部 `<x` 命中，开标签后一个字符必须是空白 / `>` / `/` 才算该标签（杀
  `<abbr>` 前缀误中）；`first_between` / `first_open_tag` 内部 `s.find(open)`
  换 `find_tag_open(s, open)`，签名与调用点不动。顺带修正 `<p` 误中
  `<picture>`/`<pre>` 同类问题（同一 helper 覆盖）。
- 新增测试 `tag_open_exact_match_skips_prefix_siblings`（约 5 断言）：
  `<abbr>` 前置于 `<a>` 时 first_open_tag 取到真 `<a>`；first_between 取真
  `<a>` 文本；`<h2>` 正常形态不回归；`<p` 不误中 `<pre>`。

## 行为变更

- 有（bug 修复）：h2/h3 内含 `<abbr>` 等前置于 `<a>` 的结果，标题/链接从
  「错位/丢失」变「正确取自 `<a>` 节点」；正常形态（`<a href=...>` 直接出现）
  解析结果不变。
